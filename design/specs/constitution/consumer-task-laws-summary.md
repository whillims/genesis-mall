## 一、消费者时间契约法（时契法）

> **文档编号**: CONSUMER-LAW-001
> **核心原则**: 时间是商场唯一的硬通货

### 1.1 核心定义

| 术语 | 定义 |
|------|------|
| **时间代价 (TC)** | 从消费者提交意图到收到首份有效产出之间的时间间隔(ms) |
| **预估时间代价 (ETC)** | 商场基于负载、生产者性能给出的预测值 |
| **实际时间代价 (ATC)** | 订单履约完成后的真实时间代价 |
| **时间溢价 (TP)** | 指定型消费中额外支付的代价增量 |
| **时间债务 (TD)** | 代价超出承受能力时形成的欠费状态 |
| **时间信用 (TCR)** | 历史履约诚信度累积 |

### 1.2 时间代价构成模型

```
ATC = T_queue + T_match + T_produce + T_transmit + T_overhead

其中:
  T_queue      = 意图在商场调度队列中的等待时间
  T_match      = 意图匹配引擎的决策时间 (通常 < 1ms)
  T_produce    = 生产者实际生产数据的时间
  T_transmit   = 产出物通过SHM总线投递到消费者矢量区块的时间
  T_overhead   = 商场内部审计、校验、日志写入的固定开销
```

### 1.3 契约缔结流程

```
步骤 1: 消费者提交意图，声明 max_time_cost_ms (最大可承受时间)
步骤 2: 商场计算 ETC，生成订单
步骤 3: 若 ETC ≤ max_time_cost_ms，契约自动缔结，订单进入 PENDING
步骤 4: 若 ETC > max_time_cost_ms，商场提供选项:
        a) 接受更高代价 (消费者确认)
        b) 切换为订阅型 (放弃指定溢价)
        c) 撤销意图
步骤 5: 消费者确认后，契约锁定，双方不得单方面变更
```

### 1.4 信用评分模型

```
TCR_new = TCR_old + α·(成功履约奖励) - β·(违约惩罚) - γ·(撤销惩罚)

信用等级:
  TCR ≥ 1000:  钻石级 → ETC 打 8 折，优先级最高
  500 ≤ TCR < 1000: 黄金级 → ETC 打 9 折，优先级高
  100 ≤ TCR < 500:  白银级 → ETC 原价，优先级中
  0 ≤ TCR < 100:    青铜级 → ETC 上浮 20%，优先级低
  TCR < 0:          失信级 → 禁止新订单，直至债务清偿
```

## 二、消费者-生产者-商场三方关系总则（三方宪章）

> **文档编号**: CONSUMER-LAW-003
> **核心原则**: 商场是唯一的信任锚点

### 2.1 三方关系第一性原理

```
公理 R-1: 商场是唯一的信任锚点。生产者与消费者之间不存在直接信任关系，
          一切信任通过商场的中介与背书建立。

公理 R-2: 生产者对消费者负有间接义务。生产者不直接服务消费者，
          生产者履约的对象是商场，商场再向消费者交付。

公理 R-3: 消费者对生产者不享有直接权利。消费者不能命令生产者生产，
          消费者只能通过商场表达意图，由商场调度生产者。

公理 R-4: 商场对双方负有绝对中立义务。商场不得偏袒任何一方，
          不得利用信息优势谋取私利。

公理 R-5: AICoder是第四方观察者。AICoder不直接参与三方交互，
          但拥有对三方行为的审查、评估、进化建议权。
```

### 2.2 关系拓扑图

```

                        │      第四方: AICoder      │

                        └─────────┬───────────────┘
                                  │
                                  ↓
┌──────────────┐      意图流      ┌──────────────┐      产出流      ┌──────────────┐
│              │ ───────────────→ │              │ ───────────────→ │              │
│   消费者     │                  │     商场     │                  │   生产者     │
│ (Consumer)   │ ←─────────────── │    (Mall)    │ ←─────────────── │ (Producer)   │
│              │     交付流       │              │     履约流       │              │
└──────────────┘                  └──────────────┘                  └──────────────┘

关键约束:
- 意图流: 单向，消费者 → 商场
- 交付流: 单向，商场 → 消费者
- 履约流: 单向，生产者 → 商场
```

## 三、消费者异常与熔断法则（熔断法）

### 3.1 异常分类

| **消费异常** | E-C | 消费者在消费过程中行为异常 |
| **资源异常** | E-R | 消费者占用的SHM资源出现异常 |
| **连接异常** | E-N | 消费者与商场的SHM连接中断 |
| **安全异常** | E-S | 消费者触发安全铁律 |
| **代价异常** | E-T | 消费者的时间代价行为异常 |

|------|------|----------|----------|----------|
| **提示** | S0 | 仅影响该消费者自身 | 下次调度时处理 | 日志记录 |

## 四、商场任务宪章

> **文档编号**: LAW-TASK-0001
> **地位**: 商场宪法之下第一级法则

### 4.1 任务定义

```
Task := { TransactionSequence[], ControlLogic, OwnerConsumer, 
          OptionalProducerMask, TimeBudget, StateVector }
```

### 4.2 任务所有权法则

- **消费者主权原则**: 任务的所有权不可转让地归属于消费者
- **生产者授权原则**: 生产者不拥有任务，但拥有进入任务的授权
- **任务集合封装权**: 消费者有权将多个任务封装为任务集合

### 4.3 六态生命周期

| 状态 | 名称 | 定义 |
|------|------|------|
| S0 | **虚空（Void）** | 任务仅存在于消费者的意图中，尚未向商场注册 |
| S1 | **创建（Created）** | 消费者提交任务描述，商场分配TaskID与SHM槽位 |
| S2 | **挂起（Pending）** | 任务等待生产者响应，或等待时间窗口开启 |
| S3 | **运行（Running）** | 至少一个生产者已认领任务，SHM中出现活跃数据流 |
| S4 | **结算（Settling）** | 交易序列完成，商场进行数据完整性校验与时间成本核算 |
| S5 | **终结（Terminated）** | 任务所有资源回收，SHM槽位释放，状态矢量归档 |

### 4.4 调度铁律

- **SHM通道唯一性**: SHM是任务数据流动的唯一合法通道
- **非阻塞主进程原则**: 商场主进程负责任务调度，但绝不参与任务的数据搬运
- **拥堵仲裁协议**: 时间契约优先 → 消费者等级 → 生产者负载均衡 → 随机扰动

## 五、任务流程操作总纲领

> **文档编号**: AICoder-TaskFlow-1.1
> **核心原则**: 函数级原子操作 · 人类审核权至上 · 商场编译进化权 · SHM矢量宪法 · 双向契约批准

### 5.1 全局唯一标识系统（GUID）

```
128位复合标志:
[31:0]   时间戳域（秒级，自Epoch起）
[63:32]  随机熵域（硬件噪声源或CSPRNG）
[79:64]  任务类型编码（16位枚举）
[95:80]  优先级权重（16位，0000为最高）
[127:96] CRC32校验域（覆盖前96位）
```

### 5.2 状态机驱动引擎

```
状态跃迁（严格顺序）:
CREATED(0) → SUBMITTED(1) → AUDITING(2) → COMPILED(3) 
→ SCHEDULED(4) → RUNNING(5) → COMPLETED(6) / FAILED(7) / CANCELLED(8)
```

### 5.3 双向契约匹配机制（增补卷二核心）

#### 5.3.1 契约前置域状态

```
DEMAND_CREATED(0x10)
    ↓
DEMAND_DECONSTRUCTED(0x11)
    ↓
MATCHED(0x12) ──→ match_score ≥ 0.80
    ↓
COST_ESTIMATED(0x13)
    ↓

    ↓

    ↓
DUAL_APPROVED(0x16)
    ↓
LOCK_ACQUIRED(0x18) ──→ 资源预占完成
    ↓
接入原有任务状态机
```

#### 5.3.2 双向批准流程

```
契约草案生成
    │
    ▼
[消费者审阅门] → 消费者阅读需求矢量、代价评估、执行窗口
    │
    ├─→ [拒绝] → 提交修改意见，返回需求解构引擎
    │
    └─→ [批准] → 消费者使用私钥签名
                 契约状态: CONSUMER_APPROVED
    │
    ▼
[商场审阅门] → 商场校验签名、复核供给矩阵、复核代价预估
    │
    ├─→ [拒绝] → 提交拒绝理由，返回匹配引擎
    │
    └─→ [批准] → 商场系统签名
                 契约状态: DUAL_APPROVED
    │
    ▼
[契约锁生效] → SHM段预分配、Worker槽位预占、编译队列预留
    │
    ▼
[任务正式出生] → 分配128位GUID，进入任务状态机
```
