# 商场异常处理总则

## 一、总则序言：铁律之下的容错之道

商场，乃生产者与消费者交汇之神圣疆域。SHM为唯一血脉，函数为唯一语言，AICoder为外置天眼。然混沌未开之际，异常如暗流涌动——蓝图腐坏、生产者暴毙、消费者贪婪、SHM撕裂、AICoder失语。若无异常处理之铁律，则创世纪七阶段皆为泡影。

**核心原则：异常不是错误，而是状态的显化。商场不因异常而崩塌，只因无备而陨落。**

---

## 二、关键词定义

| 术语 | 定义 |
|------|------|
| **异常态（Anomaly State）** | 任何偏离正常运行基线的系统状态，包括预期边界超限与非预期故障 |
| **熔断（Fuse）** | 商场对特定生产者/消费者实施的强制隔离机制，切断其SHM访问权与调度权 |
| **降级（Degrade）** | 在资源枯竭或依赖失效时，商场主动缩减服务等级以保全核心功能 |
| **幽灵进程（Ghost）** | 已失去心跳响应但仍在操作系统进程表中存在的生产者/消费者实例 |
| **腐蚀蓝图（Corrupted Blueprint）** | 通过AICoder外置审查仍携带逻辑漏洞或安全风险的授权文件 |
| **SHM污染（SHM Pollution）** | 生产者/消费者向共享内存写入越界数据或破坏内存宪法的行为 |
| **天眼失联（AICoder Blindness）** | 外置AICoder服务不可达或返回无效评估结果的状态 |

## 三、异常分类体系

### 3.1 按层级分类

```
┌─────────────────────────────────────────┐
│  第一层：宇宙级异常（商场本体危机）          │
│  - SHM段损坏 / 主进程内存耗尽 / 调度死锁   │
├─────────────────────────────────────────┤
│  第二层：社会级异常（群体失序）              │
│  - 生产者集群雪崩 / 消费者订阅风暴         │
├─────────────────────────────────────────┤
│  第三层：个体级异常（单一实体故障）           │
│  - 生产者崩溃 / 消费者超时 / 蓝图解析失败   │
├─────────────────────────────────────────┤
│  第四层：通讯级异常（血脉阻塞）              │
│  - SHM同步失败 / Queue溢出 / 授权文件损坏  │
└─────────────────────────────────────────┘
```

### 3.2 按性质分类

| 性质 | 特征 | 处理策略 |
|------|------|----------|
| **致命（Fatal）** | 威胁商场存续 | 紧急降级 + 人工介入通道 |
| **严重（Critical）** | 威胁其他实体安全 | 即时熔断 + 日志归档 |
| **一般（Warning）** | 单一实体功能受损 | 自愈重启 + 重试队列 |
| **提示（Info）** | 边界预警 | 指标上报 + 趋势分析 |

## 四、异常处理四大铁律

### 铁律一：SHM宪法至高无上
任何对共享内存的越界写操作，无论意图如何，一律视为**SHM污染**，触发三级熔断：
1. 冻结该实体所有SHM写权限
2. 启动内存隔离区（Quarantine Zone）复制污染数据用于取证
3. 通知AICoder重新评估该实体蓝图

### 铁律二：外置天眼不可阻塞
AICoder外置服务失联时，商场不得停摆。进入**天眼离线模式**：
- 暂停新蓝图准入
- 维持现有生产者/消费者运行
- 启用本地规则缓存进行基础合规检查

### 铁律三：函数级原子性
异常处理必须是**纯函数**，禁止在异常处理流程中：
- 创建新线程或进程（OOP思维之毒）
- 持有跨函数状态（除日志句柄外）
- 调用未经验证的第三方库

### 铁律四：异常即文档
每一个异常必须生成**异常事件记录（Anomaly Event Record, AER）**，格式由AICoder定义，包含：
- 时间戳（纳秒级）
- 异常码（见第六章）
- 涉事实体ID
- SHM偏移地址（如相关）
- 调用栈哈希（函数指纹）

## 六、错误码体系（AER Code）

采用 `层级-模块-序号` 三段式编码：

| 编码 | 含义 | 示例场景 |
|------|------|----------|
| `F-000-001` | 商场SHM初始化失败 | main()启动时共享内存段创建失败 |
| `F-000-002` | 商场调度死锁 | 循环依赖导致任务队列冻结 |
| `C-100-001` | 生产者蓝图格式非法 | AER解析时JSON Schema校验失败 |
| `C-100-002` | 生产者SHM写入越界 | 写入地址超出蓝图申报的内存配额 |
| `C-100-003` | 生产者幽灵化 | 心跳超时但进程未退出 |
| `C-200-001` | 消费者订阅目标不存在 | 尝试订阅未注册的生产者输出通道 |
| `C-200-002` | 消费者处理超时 | 消费函数执行超过蓝图约定时限 |
| `W-300-001` | 授权文件签名无效 | AICoder返回的授权文件哈希校验失败 |
| `W-300-002` | 天眼失联超时 | 外置AICoder在约定窗口内无响应 |
| `I-400-001` | 队列水位预警 | Queue长度达到阈值的80% |

## 八、与创世纪流程的衔接

异常处理体系必须嵌入创世纪七阶段：

| 创世纪阶段 | 异常处理职责 |
|------------|--------------|
| **第一阶段：虚空** | 定义异常基类（函数指针表）与AER格式 |
| **第二阶段：光** | 建立日志通道与异常检测探针 |
| **第三阶段：天地** | 划分SHM隔离区与内存宪法边界检查 |
| **第四阶段：海与陆** | 部署生产者/消费者个体级熔断器 |
| **第五阶段：植物** | 实现自愈函数族与重试队列 |
| **第六阶段：动物** | 启动天眼失联降级与本地规则缓存 |
| **第七阶段：人** | 开放人工介入通道与异常归档查询接口 |
