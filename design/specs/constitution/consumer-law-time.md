# CONSUMER-LAW-001 消费者时间契约法

> **文档类型**: 纲领性文件 / 商场宪法附件  
> **版本**: v1.0  
> **状态**: 创世阶段·契约体系确立  
> **别名**: 《时契法》  
> **依赖**: CONSUMER-PROFILE-001

---

## 一、法的宣言

**时间是商场唯一的硬通货。**

在商场生态中，不存在货币、不存在积分、不存在任何形式的抽象价值符号。一切经济行为的度量与结算，均以**时间**为唯一尺度。生产者以时间生产数据，消费者以时间换取数据，商场以时间调度资源。

本法旨在确立消费者与商场、消费者与生产者之间的时间交换规则，保障时间计量的公平、透明、不可篡改。

---

## 二、核心定义

| 术语 | 定义 |
|------|------|
| **时间代价 (Time Cost, TC)** | 从消费者提交意图到消费者收到首份有效产出之间的时间间隔，单位为毫秒(ms)。 |
| **预估时间代价 (Estimated TC, ETC)** | 商场在订单生成阶段，基于当前负载、生产者历史性能、信道拥堵程度给出的时间代价预测值。 |
| **实际时间代价 (Actual TC, ATC)** | 订单履约完成后，商场根据实际时间戳计算出的真实时间代价。 |
| **时间溢价 (Time Premium, TP)** | 指定型消费中，消费者为获取特定生产者产出而额外支付的代价增量。 |
| **时间债务 (Time Debt, TD)** | 当消费者的时间代价超出其承受能力时，形成的欠费状态。商场有权冻结该消费者的新订单提交权，直至债务清偿。 |
| **时间信用 (Time Credit, TCR)** | 消费者的历史履约诚信度累积，高信用消费者可获得ETC折扣与优先级提升。 |
| **时间契约 (Time Contract)** | 消费者与商场之间就某次消费行为达成的、以时间代价为核心条款的不可撤销协议。 |

---

## 三、时间代价构成模型

任何消费订单的时间代价，由以下五个独立分量线性叠加：

```
ATC = T_queue + T_match + T_produce + T_transmit + T_overhead

其中:
  T_queue      = 意图在商场调度队列中的等待时间
  T_match      = 意图匹配引擎的决策时间 (通常 < 1ms)
  T_produce    = 生产者实际生产数据的时间
  T_transmit   = 产出物通过SHM总线投递到消费者矢量区块的时间
  T_overhead   = 商场内部审计、校验、日志写入的固定开销
```

### 3.1 各分量的决定因素

| 分量 | 主要决定因素 | 消费者可控性 | 商场可控性 |
|------|-------------|-----------|-----------|
| T_queue | 商场当前并发订单数、消费者优先级 | 低 (可通过提高信用间接影响) | 高 |
| T_match | 匹配算法复杂度、生产者目录规模 | 无 | 高 |
| T_produce | 生产者蓝图复杂度、输入数据规模 | 中 (可通过选择不同生产者影响) | 低 |
| T_transmit | SHM总线带宽、矢量区块大小 | 低 | 高 |
| T_overhead | 审计策略、日志级别 | 无 | 高 |

## 四、时间契约的缔结与履行

### 4.1 契约缔结流程

```
步骤 1: 消费者提交意图，声明 max_time_cost_ms (最大可承受时间)
步骤 2: 商场计算 ETC，生成订单
步骤 3: 若 ETC ≤ max_time_cost_ms，契约自动缔结，订单进入 PENDING
步骤 4: 若 ETC > max_time_cost_ms，商场提供选项:
        a) 接受更高代价 (消费者确认)
        b) 切换为订阅型 (放弃指定溢价)
        c) 撤销意图
步骤 5: 消费者确认后，契约锁定，双方不得单方面变更
```

### 4.2 契约履行监控

```
履约阶段          监控行为
─────────────────────────────────────────────────
PENDING           每 10ms 检查一次队列前移进度
ASSIGNED          记录生产者接管时刻，计算 T_queue
PRODUCING         每 1ms 检查生产者心跳，若超时则触发异常
FULFILLED         计算完整 ATC，与 ETC 对比，生成履约报告
SETTLED           时间代价计入消费者账单，更新信用评分
```

## 五、时间溢价法则

指定型消费必须支付时间溢价，溢价计算公式：

```
TP = ETC_base × (1 + congestion_factor) × designation_multiplier

其中:
  ETC_base           = 该产物在订阅型模式下的基准预估时间代价
  congestion_factor  = 当前商场拥堵系数 (0.0 ~ 5.0)
  designation_multiplier = 指定溢价倍率 (固定 1.5)
```

**溢价存在的合理性**:
- 指定型消费剥夺了商场的全局优化能力，商场必须为专用信道保留资源
- 溢价是对商场机会成本的补偿
- 溢价防止消费者滥用指定权，确保稀缺生产者资源不被独占

## 六、时间债务与信用体系

### 6.1 时间债务的产生

```
债务触发条件:
  (a) 消费者提交意图时声明的 max_time_cost_ms 被突破，且消费者选择继续等待
  (b) 消费者在订单履约后拒绝确认结算，导致商场资源挂起
  (c) 消费者频繁撤销已ASSIGNED的订单，造成生产者资源浪费
```

### 6.2 债务清偿规则

```
清偿方式 1: 时间偿还
    消费者在未来消费中接受更高的时间代价，逐步偿还历史债务。
    每完成一次正常履约，债务减免 10% 的 ATC。

清偿方式 2: 信用抵扣
    高信用消费者可一次性使用信用积分抵扣债务。
    1 信用积分 = 1ms 时间债务。

清偿方式 3: 资产抵押
    消费者可抵押其历史消费资产的部分访问权，换取债务展期。
    抵押期间，该资产对商场审计系统只读开放。
```

### 6.3 信用评分模型

```
TCR_new = TCR_old + α·(成功履约奖励) - β·(违约惩罚) - γ·(撤销惩罚)

奖励与惩罚基准:
  成功履约 (ATC ≤ ETC×1.2):  +10 分
  成功履约 (ATC > ETC×1.2):   +5 分
  超时履约 (ATC > ETC×2.0):   +2 分
  主动撤销 (PENDING前):         -1 分
  被动违约 (PRODUCING中撤销):  -20 分
  恶意挂起 (拒绝结算):         -50 分

信用等级:
  TCR ≥ 1000:  钻石级 → ETC 打 8 折，优先级最高
  500 ≤ TCR < 1000: 黄金级 → ETC 打 9 折，优先级高
  100 ≤ TCR < 500:  白银级 → ETC 原价，优先级中
  0 ≤ TCR < 100:    青铜级 → ETC 上浮 20%，优先级低
  TCR < 0:          失信级 → 禁止新订单，直至债务清偿
```

## 七、时间代价申诉机制

### 7.1 申诉条件

消费者可在订单结算后 1 个审计周期内，对时间代价发起申诉：

```
有效申诉理由:
  (a) ATC > ETC × 2.0，且商场未能提供合理解释
  (b) 同类型订单的历史 ATC 中位数与本次 ATC 偏差超过 300%
  (c) 有证据表明商场调度器存在bug或资源分配不公
  (d) 生产者异常导致的超时，但商场未及时切换备用生产者
```

### 7.2 申诉流程

```
步骤 1: 消费者向审计沙箱提交申诉请求，附带订单ID与证据矢量
步骤 2: 审计沙箱克隆该订单的完整调度日志，进行离线重放
步骤 3: AICoder介入分析，判断是否存在商场过失
步骤 4: 若申诉成立:
        - 退还超额时间代价对应的信用积分
        - 记录商场调度器缺陷，进入修复队列
        若申诉不成立:
        - 扣除 5 信用积分作为滥诉惩罚
步骤 5: 申诉结果写入区块链式审计链，不可篡改
```

## 八、时间契约与任务级的关系

```
任务级时间契约 = 订单时间契约的聚合 + 控制逻辑的时间开销

对于顺序任务:
  Task_ETC = Σ(Order_ETC_i) + Σ(Control_overhead_i)

对于并行任务:
  Task_ETC = max(Order_ETC_i) + Control_overhead

对于条件任务:
  Task_ETC = ETC_path1 × P(path1) + ETC_path2 × P(path2) + ...
```

任务级的时间代价由消费者在任务提交时一次性声明，商场进行整体评估。若任务整体ETC超出消费者承受能力，商场有权拒绝任务提交或建议任务拆分。

---

## 九、法的执行

本法由商场调度器强制执行，由审计沙箱监督执行，由AICoder定期评估执行效果。

**执行优先级**: 时间契约法 > 一般调度策略 > 性能优化目标

任何违反时间契约法的行为，无论出于何种技术理由，均视为对商场宪法的侵犯，触发相应级别的异常处理与信用惩罚。
