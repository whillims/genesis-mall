## 一、八条铁律体系

### 铁律一：函数无状态

> **函数不维护跨调用状态，状态仅存于SHM。**

- 每次函数调用后，所有局部变量清零
- 状态持久化必须通过SHM矢量显式写入
- 禁止闭包、全局变量、静态变量等隐式状态

**违规后果**: AICoder审核拒绝，函数无法进入商场执行。

---

### 铁律二：商场运送数据

> **数据必须经过SHM路由，生产者不能直接投递给消费者。**

- 生产者 → SHM矢量 → 商场路由 → 消费者
- 禁止生产者与消费者之间的直接通道（管道、socket、共享内存绕过）
- 商场作为唯一物流通道，确保可追溯、可审计、可调度

**违规后果**: 商场拒绝加载包含直接通信逻辑的函数。

---

### 铁律三：消费者验收

> **消费者拥有最终判定权，生产者必须提供测试资料。**

- 消费者可接受或拒绝数据，无需说明理由
- 生产者必须在蓝图中声明测试用例（TC编号）
- 消费者验收状态写入审计日志，影响生产者信誉分

**违规后果**: 消费者拒绝的数据不计入生产者收益，连续拒收触发信誉降级。

---

### 铁律四：蓝图不可篡改

> **生产者可见代码但不可直接修改，必须通过蓝图修订流程。**

- 蓝图修改路径: 修订文档 → AICoder重新审核 → 生成新授权文件
- 商场执行的是授权文件中的编译产物，不是蓝图原文
- 版本演进通过授权文件链式哈希追溯

**违规后果**: 任何试图绕过AICoder直接修改执行逻辑的行为被视为安全违规，Worker冻结。

---

### 铁律五：AICoder中立

> **AICoder仅代表规则执行，不参与利益博弈。**

- AICoder审核语法、安全、协议、测试完备性
- AICoder不评判商业价值、不干预定价、不偏袒任何生产者
- AICoder外置于商场，商场稳定性不受AICoder崩溃影响

**违规后果**: 若检测到AICoder输出包含利益倾向性内容，商场拒绝采纳该审核结果。

---

### 铁律六：数据资产发送权

> **生产者拥有数据所有权，但发送行为不得损害商场利益。**

- 生产者对其生成的数据资产（IQ采样、遥测帧、分析报告）拥有完整所有权
- 生产者有权决定数据发送至何处（消费者选择）
- 但发送行为不得: 阻塞商场通道、注入恶意数据、试图操控其他生产者

**违规后果**: 损害商场利益的发送行为触发安全审计，严重者冻结发送权限。

---

### 铁律七：单向漏斗

> **外域接收通道禁止反窥，禁止内域信息外泄。**

- 外域 → 商场: 允许（接收遥测、指令）
- 商场 → 外域: 受控（需通过发射端审核）
- 禁止从接收通道反向探测商场内部状态

**违规后果**: 检测到反窥行为立即切断通道，涉事生产者信用分清零。

---

### 铁律八：蓝图所有权与交易禁令

> **生产者拥有蓝图完整所有权，商场禁止内部蓝图交易，交易纠纷由人类社会裁定。**

- **所有权四权能**: 占有、使用、收益、处分
- **商场内部禁止**: 直接买卖、拍卖竞价、租赁授权、抵押质押、期货期权
- **人类社会溢出**: 蓝图在人类社会中的流动（复制、传播、交易）不属于商场管辖

**违规后果**: 商场拒绝执行任何包含交易逻辑的函数，交易纠纷提交人类社会裁定。

## 二、主权分离架构

### 2.1 三层主权模型

```
┌─────────────────────────────────────────────────────────────┐
│                    人类主权层（最高）                         │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  设计审核权                                          │   │
│  │  - 蓝图提交与修订                                    │   │
│  │  - AICoder规则制定                                   │   │
│  │  - 商场宪法修正                                      │   │
│  │  - 交易纠纷裁定（人类社会法律）                       │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    商场主权层（中间）                         │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  编译进化权 + 调度权                                 │   │
│  │  - AICoder调用与审核                                 │   │
│  │  - 授权文件生成与管理                                │   │
│  │  - 算力进程池调度                                    │   │
│  │  - SHM矢量管理                                       │   │
│  │  - 安全监控与审计                                    │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    Worker主权层（基础）                       │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  执行权（被严格约束）                                 │   │
│  │  - 函数执行（无状态）                                │   │
│  │  - 数据生产（经SHM）                                 │   │
│  │  - 数据消费（经SHM）                                 │   │
│  │  ❌ 禁止拥有编译权                                   │   │
│  │  ❌ 禁止拥有调度权                                   │   │
│  │  ❌ 禁止拥有安全裁定权                               │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 主权边界原则

| 层级 | 权力范围 | 禁止越界 |
|------|----------|----------|
| 人类 | 设计审核、宪法修正、交易裁定 | 不得直接干预商场调度 |
| 商场 | 编译进化、算力调度、安全监控 | 不得拥有设计审核权、不得仲裁交易纠纷 |
| Worker | 函数执行、数据生产消费 | 不得拥有编译权、调度权、安全裁定权 |

## 三、资产治理体系

### 3.1 两类资产对比

| 维度 | 数据资产 | 蓝图资产 |
|------|----------|----------|
| **本质** | 运行时信息单元 | 设计意图的结构化表达 |
| **形态** | 二进制数据包 | Markdown文档 |
| **存储位置** | SHM矢量 | 蓝图仓库 |
| **生命周期** | 瞬时性 | 持久性 |
| **流动空间** | 商场内部 | 人类社会 |
| **所有权** | 生产者/Worker | **生产者完整所有权** |

### 3.2 数据资产治理

- **产生**: Worker运行时生成
- **流动**: SHM矢量路由
- **消费**: 消费者验收
- **销毁**: 消费后自动释放
- **权属**: 生产者拥有，可自由发送（不损害商场利益前提下）

### 3.3 蓝图资产治理

- **产生**: 人类设计者或AICoder审核后固化
- **托管**: 商场蓝图仓库（不改变所有权）
- **执行**: 商场加载授权文件执行
- **演进**: 修订→重新审核→新版本
- **权属**: 生产者拥有四权能（占有、使用、收益、处分）
- **交易**: 商场内部禁止，人类社会自由

## 五、人类社会溢出机制

### 5.1 溢出原则

> **商场能力边界外的事务，溢出至人类社会裁定。**

### 5.2 溢出事务清单

| 事务类型 | 商场角色 | 人类社会角色 |
|----------|----------|-------------|
| 蓝图技术审核 | 执行审核 | 不参与 |
| 蓝图安全执行 | 执行调度 | 不参与 |
| 蓝图所有权争议 | 提供审计日志作为证据 | 法院/仲裁裁定归属 |
| 蓝图交易纠纷 | 提供技术事实（提交时间戳） | 合同法裁定违约责任 |
| 蓝图侵权指控 | 提供版本演进记录 | 知识产权法庭裁定 |

### 5.3 溢出流程

```
生产者A与生产者B争夺蓝图X所有权
    │
    ├──→ 商场提供证据包
    │       ├─ 蓝图提交时间戳
    │       ├─ 版本演进记录
    │       ├─ 授权文件链
    │       └─ 审计日志
    │
    └──→ 人类社会裁定
            ├─ 法院/仲裁庭审理
            ├─ 裁定所有权归属
            └─ 败诉方承担法律责任

裁定后:
    ├─ 若B获得所有权 → B以新所有者身份重新提交
    ├─ AICoder重新审核（只审技术合规性）
    └─ 商场执行（不关心B如何获得蓝图）
```

## 六、商场监控权边界

### 6.1 监控权与建议权

#### 6.1.1 监控定义

> **商场监控是"观察权"，不是"干预权"。**

商场通过全链路观测收集交易数据、性能指标、安全事件，用于审计追溯和异常检测。监控数据本身不直接触发任何惩罚或干预行为。

#### 6.1.2 建议权定义

> **商场建议权是调度权的自然延伸，不是干预权。**

商场基于监控数据分析，主动向管理者或消费者提出优化建议。建议以结构化事件产品形式发布，建议的执行权归属不同角色：

| 建议类型 | 执行者 | 权限性质 |
|----------|--------|----------|
| 算力再分配、产出节流 | 商场调度器 | 调度权范围内，直接执行 |
| 优先级调整、生产者切换 | 消费者 | 建议权，需消费者确认 |
| 蓝图优化 | AICoder/人类 | 建议权，溢出至人类社会 |

**建议权 ≠ 干预权**: 商场可以提出建议，但不得未经确认修改消费者意图或人类蓝图；商场可以基于调度权直接执行资源调节，但不得基于建议对任何角色进行惩罚（惩罚必须基于明确的违宪行为）。

### 6.2 监控范围

| 端点 | 监控内容 | 用途 |
|------|----------|------|
| **接收端** | 源IP、帧大小、接收时间戳、入关延迟 | 审计日志、性能分析、异常检测 |
| **发射端** | 目标IP、指令内容哈希、发送时间戳、ACK状态 | 闭环验证、故障追溯 |
| **边界网关** | 函数调用链、缓冲区访问范围、反窥行为 | 安全审计、AICoder复核 |

### 6.3 监控数据使用边界

| 允许用途 | 禁止用途 |
|----------|----------|
| 审计日志记录 | 作为信用分惩罚依据（除非明确违规） |
| 性能分析与优化 | 干涉生产者的数据发送权 |
| 异常检测与告警 | 限制蓝图的自由流动 |
| 安全事件追溯 | 分析生产者商业意图 |

### 6.4 与系统层的关系

| 层面 | 系统层职责 | 商场监控职责 | 关系 |
|------|-----------|-------------|------|
| 网络协议 | TCP/IP拥塞控制、重传 | 记录流量元数据 | 并行不冲突 |
| 边界网关 | 解封→转换→SHM写入 | 监督反窥行为 | 监督关系 |
