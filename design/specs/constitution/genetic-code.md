## 基因概览

项目"创世纪"是一个微型商场模式系统，核心理念是通过**授权文件**驱动、**函数范式**约束、**三界隔离**架构，构建一个可审计、可进化、抗篡改的智能代理运行平台。

---

## 一、哲学基因（核心理念）

### 1.1 三界隔离原则

```
┌─────────────────────────────────────────────────────────────┐
│                      三界隔离架构                            │
├─────────────────────────────────────────────────────────────┤
│  生产者域        │  AICoder域         │  商场域            │
│  Worker/探针     │  外置审查节点      │  主进程/编译器      │
├─────────────────────────────────────────────────────────────┤
│  输入: 契约蓝图   │  输入: 蓝图         │  输入: 授权文件     │
│  输出: 蓝图文件   │  输出: 授权文件     │  输出: 函数句柄     │
│  禁区: 不提交代码 │  禁区: 不入场通信   │  禁区: 不修改语义   │
└─────────────────────────────────────────────────────────────┘
```

**核心戒律**：授权文件即真理，代码只在授权书中存在，商场永不触碰外部代码源。

### 1.2 函数范式铁律（OOP禁止）

| 禁令 | 原因 | 替代方案 |
|------|------|----------|
| 禁止类定义 | 编译权私有化 | 纯函数 |
| 禁止继承链 | 封建血统论 | 函数组合 |
| 禁止私有状态 | 权力暗角 | SHM外置 |
| 禁止多态暗箱 | 运行时黑箱 | 静态绑定 |
| 禁止副作用 | 行为不可追踪 | callback_publish |
| 禁止网络数据库 | 数据脱离审计 | SHM矢量空间 |

### 1.3 零原则体系

```
┌────────────────────────────────────────────────┐
│           三大零原则（不可违背）                 │
├────────────────────────────────────────────────┤
│  1. 零全局状态   → 无static/无global/无单例     │
│  2. 零堆分配     → 无malloc/new/calloc         │
│  3. 零系统调用   → 无文件IO/无网络/无进程管理   │
└────────────────────────────────────────────────┘
```

```json
{
  "auth_header": {           // 第一节：授权对象元数据

    "auth_version": "1.0"

  "design_meta": {           // 第二节：设计元数据
    "function_name": "keyboard_echo",
    "input_schema": [...],
    "output_schema": [...],
    "side_effect": ["stdout_write"],
    "stack_estimate_bytes": 2048
  },
  "source_code": {           // 第三节：源代码+哈希
    "language": "Python",
    "code": "def keyboard_echo...",
    "hash_sha256": "5e68b5f5..."
  },
  "compiled_binary": {        // 第四节：PYC编译产物
    "format": "CPython-PYC",

    "hash_sha256": "73499708..."
  },
  "verification_report": {    // 第五节：验收测试
    "static_analysis_pass": true,
    "behavior_test_pass": true,
    "test_cases": [...]
  }
}
```

### 2.2 七步验证流程

```
Step1 格式校验     → 检查5字段完整性
Step2 签名验证     → 验证AICoder指纹
Step3 哈希校验     → 源码/PYC/声明三者一致
Step4 静态规则     → 扫描OOP/系统调用/网络数据库
Step5 沙箱加载     → PYC marshal.loads + exec
Step6 回归测试     → 逐条执行verification_report
Step7 函数注册    → 分配FUNC-HANDLE-XXXX
```

### 2.3 七维审查清单

| 维度 | 审查内容 | 通过条件 |
|------|----------|----------|
| D1 形式规范 | 签名/命名/契约完整性 | 符合命名宪章 |
| D2 安全铁律 | 零全局/零堆/零系统调用 | 全绿通过 |
| D3 语义一致 | 伪代码与契约描述自洽 | 无歧义 |
| D4 性能资源 | 栈深/时间/SIMD可行性 | 在承载范围内 |
| D5 测试覆盖 | 边界/异常/正常场景 | 至少覆盖底线 |
| D6 编译可行 | 无警告编译通过 | 零warning |
| D7 生态兼容 | SHM矢量可接管/可入线程池 | 兼容性验证 |

## 三、SHM矢量空间基因

### 3.1 矢量六状态机

```
UNBORN (0) ──创建──→ ACTIVE (1) ──封印──→ SEALED (2)
                              │                    │
                              │              ┌─────┴─────┐
                              ↓              ↓           ↓
                         ARCHIVED (3)   CORRUPTED (4)   VOID (5)
                              │                    │
                              └────────┬───────────┘
                                       ↓
                                  统一销毁
```

### 3.2 矢量内存布局

```
┌──────────────────────────────────────────────────────────┐
│  SHM矢量内存块结构（固定头尾+弹性体）                        │
├──────────────────────────────────────────────────────────┤
│  [4B魔数MALL] [2B版本] [1B状态] [1B类型码] [32B所有者]      │ ← 82字节头部
│  [2B所有者长度] [32B保留] [8B数据大小] [32B校验和]            │
├──────────────────────────────────────────────────────────┤
│  [N字节数据体]                                              │ ← 可变大小
├──────────────────────────────────────────────────────────┤
│  [4B魔数LLAM] [8B时间戳] [4B序列号]                         │ ← 16字节尾部
└──────────────────────────────────────────────────────────┘
```

### 3.3 门禁校验机制

```python
def shm_gate_check(ctx, caller_id, vec_name, intent):
    # 1. 存在性检查
    # 2. 封印状态检查（封印矢量禁止写入）
    # 3. 损坏状态检查
    # 4. 销毁状态检查
    # 5. 权限检查（所有者/商场/AICoder三角校验）
    return (allowed, err_code, reason)
```

## 四、异常处理基因

### 4.1 异常分类体系

| 阶段 | 异常代码前缀 | 典型异常 | 处置动作 |
|------|--------------|----------|----------|
| AICODER | C-100 | 蓝图格式错误/安全违规 | REJECT |
| MALL_AUTH | W-300 | 编译失败/签名错误 | SILENT_DROP / SECURITY_ALERT |
| MALL_RUNTIME | F-000 | 栈溢出/超时/副作用越界 | REVOKE_HANDLE / QUARANTINE |
| FUNCTION | I-400 | 输入错误/运行时异常 | FALLBACK |

### 4.2 异常处置四阶段

```
┌─────────────────────────────────────────────────────────────┐
│  异常处置四阶段                                              │
├─────────────────────────────────────────────────────────────┤
│  Phase 1: AICoder阶段   → REJECT / RETRY                   │
│  Phase 2: MALL_AUTH阶段 → SILENT_DROP / SECURITY_ALERT      │
│  Phase 3: MALL_RUNTIME  → REVOKE_HANDLE / QUARANTINE        │
│  Phase 4: FUNCTION阶段  → FALLBACK                          │
└─────────────────────────────────────────────────────────────┘
```

## 五、架构基因

### 5.1 三进程架构

```
┌──────────────────────────────────────────────────────────────┐
│                      主进程 Manager                           │
│              process_manager.py (multiprocessing)            │
│                   创建Queue │ 启动子进程 │ 监控                │
└──────────────────────────────────────────────────────────────┘
                ↓ req_queue ↑ resp_queue
    ┌───────────┴───────────┐    ┌───────────┴───────────┐
    │   商场本体 (子进程)     │    │   FastAPI通讯层      │
    │   mall_core.py        │    │   fastapi_worker.py  │
    │   纯业务逻辑 │ 无HTTP   │    │   HTTP接口 │ Queue转发│
    └───────────────────────┘    └───────────────────────┘
```

### 5.2 Queue通讯协议

```python
# 请求格式
{"req_id": "uuid", "action": "login", "params": {"user": "admin"}}

# 响应格式
{"req_id": "uuid", "status": "success", "data": {...}}
```

### 5.3 Nginx钢铁脊椎

```
浏览器 ──→ Nginx(80/443) ──→ FastAPI(8000) ──→ 商场本体
              │                │               │
              ├─ 静态资源服务   ├─ 反向代理     ├─ 业务逻辑
              ├─ SSL/TLS终端   └─ 请求转发     └─ SHM管理
              └─ 安全过滤
```

## 十、核心价值观提炼

| 价值观 | 体现 |
|--------|------|
| **透明即信任** | 所有代码行为必须可审计，无隐藏状态 |
| **授权即法律** | 授权文件是唯一合法凭证，不可篡改 |
| **隔离即安全** | 三界物理隔离，AICoder永不入场 |
| **函数即原子** | 最小行为单元，无OOP封装，无继承 |
| **SHM即血脉** | 共享内存是唯一通讯通道，禁止其他IPC |
| **进化即生长** | 蓝图驱动生长，授权文件可追溯历史 |
