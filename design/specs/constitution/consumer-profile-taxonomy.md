## 一、消费者类型总谱

商场生态中的消费者按**消费相态**与**数据终态**划分为六大基类，所有实际消费者均为这六类的函数级组合或特化：

```
                        消费者基类谱系
                             │
        ┌──────────┬─────────┼─────────┬──────────┐
        ↓          ↓         ↓         ↓          ↓
    终端型      文件型     网络型     分析型      控制型
   (Terminal)  (File)   (Network)  (Analytics) (Control)
        │          │         │         │          │
        └──────────┴─────────┴─────────┴──────────┘
                             │
                        容器型 (Container)
                        ├─ UI组件容器 (Web Plaza)
                        ├─ 任务集容器 (Task Bundle)
                        └─ 审计沙箱容器 (Audit Sandbox)
```

## 二、六类消费者深度画像

### 2.1 终端型消费者 (Consumer-Terminal, CT)

| 属性 | 描述 |
|------|------|
| **画像编码** | `M-sub/L0/S0/B∞/C1` |
| **消费相态** | 字符流 / 格式化文本 / 实时日志 |
| **典型实现** | Console消费者 (BP-0002-console) |
| **SHM交互** | 订阅生产者输出矢量，实时渲染至标准输出 |
| **生命周期** | 会话态，随终端会话启停 |
| **特殊能力** | 可同时订阅多个生产者输出，多路复用显示 |
| **风险等级** | 低。仅消费，无外发，无持久化 |

**函数级行为模型**:
```python
def consumer_terminal_run(intent_vector, shm_handle, session_id):
    # 1. 向商场注册消费意图
    # 2. 获取订阅生产者列表的SHM掩码
    # 3. 轮询/事件驱动读取SHM产出矢量
    # 4. 格式化渲染至stdout
    # 5. 会话终止时显式注销
    pass
```

### 2.2 文件型消费者 (Consumer-File, CF)

| 属性 | 描述 |
|------|------|
| **画像编码** | `M-mix/L2/S1/B1/C2` |
| **消费相态** | 结构化文件 / 数据快照 / 日志归档 |
| **典型实现** | 数据落盘消费者、日志归档消费者 |
| **SHM交互** | 批量读取SHM矢量区块，按格式写入文件系统 |
| **生命周期** | 持久态，可跨会话运行 |
| **特殊能力** | 可配置滚动策略、压缩策略、分片策略 |
| **风险等级** | 中。涉及文件系统IO，需沙箱隔离 |

**核心约束**:
- 文件写入路径必须在商场沙箱目录内，禁止逃逸至系统根目录
- 文件型消费者本身也是生产者（文件是产物），但文件内容的所有权归原始消费者

---

### 2.3 网络型消费者 (Consumer-Network, CN)

| 属性 | 描述 |
|------|------|
| **画像编码** | `M-spec/L1/S2/B2/C1` |
| **消费相态** | 网络报文 / 遥测数据 / 外发流 |
| **典型实现** | 网络遥测消费者、数据上报消费者 |
| **SHM交互** | 读取SHM矢量，封装为网络报文外发 |
| **生命周期** | 会话态或持久态 |
| **特殊能力** | 协议适配、流量整形、断线重传 |
| **风险等级** | **高**。涉及商场与外域边界，受安全铁律严格监管 |

**外域铁律** (参见 CONSUMER-LAW-002):
- 网络型消费者外发的数据资产必须属于该消费者自身消费产物
- 禁止转发其他消费者的SHM矢量数据
- 禁止外发商场内部拓扑、生产者蓝图、调度日志等元数据
- 商场保留对所有外发报文的镜像审计权

---

### 2.4 分析型消费者 (Consumer-Analytics, CA)

| 属性 | 描述 |
|------|------|
| **画像编码** | `M-mix/L1/S1/B2/C2` |
| **消费相态** | 统计报表 / 频谱图 / 特征向量 / 异常标记 |
| **典型实现** | 数据分析Worker、频谱分析消费者、脉冲参数提取器 |
| **SHM交互** | 多源SHM矢量聚合 → 算法处理 → 新SHM矢量产出 |
| **生命周期** | 持久态 |
| **特殊能力** | 跨生产者数据融合、时序对齐、特征提取 |
| **风险等级** | 中。混合角色：既是消费者也是生产者 |

**混合角色声明**:
分析型消费者是商场中唯一的**混合态实体**。它消费上游生产者的原始数据，经过算法加工后产出新的数据资产，这些新资产可被其他消费者订阅。

但严格区分：
- **作为消费者**: 受消费者权利法案保护，承担消费者义务
- **作为生产者**: 必须拥有独立蓝图，通过AICoder审查，获得授权文件

分析型消费者不得在同一函数体内同时执行消费与生产行为，必须通过两个独立的函数级Worker实现，物理隔离。

---

### 2.5 控制型消费者 (Consumer-Control, CC)

| 属性 | 描述 |
|------|------|
| **画像编码** | `M-spec/L0/S3/B∞/C3` |
| **消费相态** | 控制指令 / 反馈信号 / 状态机跳转 |
| **典型实现** | 闭环控制消费者、设备驱动消费者 |
| **SHM交互** | 消费传感器数据 → 计算控制量 → 写入执行器SHM矢量 |
| **生命周期** | 永恒态，随商场启动而启动，随商场终止而终止 |
| **特殊能力** | 硬实时响应、PID/状态机控制、故障安全模式 |
| **风险等级** | **极高**。控制型消费者的异常可直接导致物理世界损害 |

**控制型消费者安全铁律**:
```
铁律 C-1: 控制型消费者必须通过独立的硬件看门狗监控。
铁律 C-2: 控制指令输出必须经过商场安全闸的双人校验机制。
铁律 C-3: 任何控制指令的SHM矢量写入必须附带时间戳与序列号，
          防止重放攻击与延迟攻击。
铁律 C-4: 控制型消费者必须实现故障安全(fail-safe)模式，
          当商场通信中断时自动进入安全态。
```

### 2.6 容器型消费者 (Consumer-Container, CCn)

| 属性 | 描述 |
|------|------|
| **画像编码** | `M-sub/L1/S1/B1/C2` |
| **消费相态** | UI组件树 / 任务集视图 / 审计仪表盘 |
| **典型实现** | Web消费者广场、任务集容器、审计沙箱可视化 |
| **SHM交互** | 聚合多个消费者相的SHM矢量，进行可视化编排 |
| **生命周期** | 持久态 |
| **特殊能力** | 消费者相的组合、布局、交互路由 |
| **风险等级** | 低。纯展示层，不直接参与数据生产 |

**容器型消费者三定律**:
```
定律 V-1: 容器不拥有数据，只拥有视图的渲染权。
定律 V-2: 容器内的每个消费者相必须独立渲染，
          任一相的崩溃不得波及其他相。
定律 V-3: 容器的布局配置属于容器自身资产，
          但容器内展示的数据资产归属原始消费者。
```

## 三、消费者分级矩阵

| 分级 | 标识 | 画像特征 | 典型场景 | 商场资源配额 |
|------|------|----------|----------|-------------|
| **基础级** | C-L0 | 低敏感度、低代价、短生命周期 | Console日志、临时监控 | SHM: 1MB / 优先级: 低 |
| **标准级** | C-L1 | 中等敏感度、可承受延迟 | 文件归档、Web展示 | SHM: 10MB / 优先级: 中 |
| **高级** | C-L2 | 高敏感度、实时要求、长生命周期 | 网络遥测、数据分析 | SHM: 100MB / 优先级: 高 |
| **核心级** | C-L3 | 绝密敏感度、硬实时、永恒态 | 闭环控制、安全监控 | SHM: 1GB / 优先级: 最高 |

## 四、消费者组合范式

实际商场场景中，单一消费者往往由多个基类函数组合而成：

```
示例: 微波TR测试系统的"频谱监控面板"

┌─────────────────────────────────────────────┐
│           容器型消费者 (Web Plaza)           │
│  ┌─────────────┐    ┌──────────────────┐   │
│  │ 终端型相    │    │ 分析型相         │   │
│  │ (实时日志)  │    │ (频谱瀑布图)     │   │
│  └─────────────┘    └──────────────────┘   │
│  ┌─────────────┐    ┌──────────────────┐   │
│  │ 文件型相    │    │ 控制型相(只读)   │   │
│  │ (历史回放)  │    │ (设备状态指示)   │   │
│  └─────────────┘    └──────────────────┘   │
└─────────────────────────────────────────────┘
```

组合规则:
- 组合消费者必须以容器型为根，其他类型为叶
- 叶节点之间的SHM数据不得直接共享，必须通过容器路由
- 组合消费者的整体画像取其叶节点的最高敏感度与最短生命周期
