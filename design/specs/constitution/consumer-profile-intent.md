## 一、意图的本质

**消费者意图**是商场经济系统的原子需求单元。它不是简单的"我想要数据"，而是一个包含数据特征、时效约束、代价预期、失败策略的**结构化契约请求**。

意图的哲学定位:
```
生产者拥有蓝图所有权 → 定义"能生产什么"
消费者拥有意图所有权 → 定义"需要什么"
商场拥有匹配调度权   → 定义"如何连接"
AICoder拥有进化审查权 → 定义"能否更好"
```

## 二、意图数据结构 (Intent Vector)

意图在SHM中以标准化矢量结构存储，所有字段为定长，禁止变长嵌套：

```c
// 意图矢量结构 (定长 512字节)
struct IntentVector {
    // 元数据区 (64字节)
    char   intent_id[32];        // 意图唯一标识 UUID
    char   consumer_id[32];      // 消费者唯一标识

    // 需求描述区 (128字节)
    char   product_signature[64]; // 产物特征签名 (如 "spectrum.f32.4096")
    char   producer_hint[64];     // 生产者提示 (可选，指定型消费必填)

    // 约束区 (128字节)
    uint32_t latency_class;       // 时效等级 L0-L3
    uint32_t sensitivity_class;   // 敏感度 S0-S3
    uint64_t max_time_cost_ms;    // 最大可承受时间代价 (毫秒)
    uint64_t min_interval_ms;     // 最小消费间隔 (防抖动)
    uint32_t retry_policy;        // 重试策略 0=放弃 1=降级 2=阻塞 3=熔断

    // 掩码区 (64字节)
    uint64_t producer_mask;       // 生产者掩码 (指定型消费使用)
    uint64_t product_mask;        // 产物类型掩码

    // 保留区 (128字节)
    char   reserved[128];         // 未来扩展 / 审计指纹
};
```

## 四、消费模式详解

### 4.1 订阅型消费 (Subscription Mode)

```
消费者 ──→ 商场: "我订阅所有 product_signature='spectrum.f32.4096' 的产出"
商场 ──→ 消费者: 当任意匹配生产者有新产出时，通过SHM矢量投递
```

特征:
- 消费者不指定具体生产者
- 商场意图匹配引擎负责路由
- 适合广播型、监控型场景
- 时间代价由商场根据当前负载动态估算

**订阅型意图示例**:
```json
{
  "intent_id": "INT-20260510-001",
  "consumer_id": "CON-UI-001",
  "product_signature": "spectrum.f32.4096",
  "producer_hint": "",              // 空表示不指定
  "latency_class": 1,               // L1 准实时
  "sensitivity_class": 1,             // S1 内部
  "max_time_cost_ms": 500,
  "min_interval_ms": 50,
  "retry_policy": 1,                // 1=降级
  "producer_mask": 0x00000000,      // 掩码0表示任意生产者
  "product_mask": 0x00000001        // 产物掩码
}
```

### 4.2 指定型消费 (Designation Mode)

```
消费者 ──→ 商场: "我指定生产者 PROD-SPEC-001 的产出，我愿意承受更高时间代价"
商场 ──→ 消费者: 仅当指定生产者有产出时投递，若生产者异常则按retry_policy处理
```

特征:
- 消费者明确指定生产者ID
- 商场绕过匹配引擎，直接建立专用SHM信道
- 适合确定性、溯源型场景
- 时间代价包含"指定溢价"，由商场 congestion 模型计算

**指定型意图示例**:
```json
{
  "intent_id": "INT-20260510-002",
  "consumer_id": "CON-CTRL-001",
  "product_signature": "feedback.f32.8",
  "producer_hint": "PROD-CTRL-001",   // 指定生产者
  "latency_class": 0,                 // L0 实时
  "sensitivity_class": 3,             // S3 绝密
  "max_time_cost_ms": 10000,          // 可承受高代价
  "min_interval_ms": 1,
  "retry_policy": 2,                  // 2=阻塞等待
  "producer_mask": 0x00000001,        // 指定生产者掩码位
  "product_mask": 0x00000002
}
```

### 4.3 混合型消费 (Hybrid Mode)

混合型消费是订阅型与指定型的动态组合：
- **主路径**: 指定型，确保核心数据源的确定性
- **辅路径**: 订阅型，补充相关数据源用于交叉验证或上下文丰富

混合型消费者必须声明**主辅优先级**，商场调度器确保主路径的SHM信道永不阻塞，辅路径在资源紧张时可被降级。

## 五、意图匹配引擎设计原则

意图匹配引擎是商场的核心组件，负责将消费者意图与生产者产出进行高效、安全、公平的匹配。

### 5.1 匹配算法铁律

```
铁律 M-1: 匹配必须是纯函数
    match(intent_vector, producer_catalog) → order_vector
    相同输入必须产生相同输出，禁止随机性。

铁律 M-2: 匹配必须可审计
    每一次匹配决策必须留下审计指纹，包括:
    - 匹配时刻的商场负载状态
    - 所有候选生产者的评分快照
    - 最终选择的理由编码

铁律 M-3: 匹配必须公平
    同一意图在不同时间提交，若商场状态相同，
    匹配结果必须相同。禁止对消费者身份进行歧视性加权。

铁律 M-4: 匹配必须可降级
    当无完全匹配的生产者时，引擎必须提供:
    - 最接近的替代方案
    - 降级后的预期时间代价
    - 消费者确认/拒绝的交互通道
```

### 5.2 生产者评分模型

商场为每个生产者维护一个**稳定性评分 (Stability Score, SS)**，影响匹配优先级：

```
SS = α·(历史履约率) + β·(平均产出延迟的倒数) + γ·(蓝图审查评级) - δ·(异常次数)

其中:
  α = 0.4, β = 0.3, γ = 0.2, δ = 0.1
  所有参数由AICoder定期评估调整，商场只执行，不解释
```

## 六、订单与任务的关系

```
任务 (Task) = 订单序列 (Order Sequence) + 交易控制逻辑 (Transaction Control)

一个任务可以包含多个订单:
- 顺序执行: Order-1 → Order-2 → Order-3 (流水线)
- 并行执行: Order-1 || Order-2 || Order-3 (广播)
- 条件执行: Order-1 → [if success] → Order-2 / [if fail] → Order-3 (分支)
```

任务所有权属于消费者，但任务的调度执行权属于商场。消费者可以:
- 提交任务
- 查询任务状态
- 暂停/恢复任务
- 取消未履约订单
- 但不得直接干预商场调度器的内部决策

## 七、意图撤销与契约解除

消费者在订单进入 `PRODUCING` 状态前，有权撤销意图：

```
撤销条件:
  - 订单状态 ∈ {CREATED, PENDING, ASSIGNED}
  - 消费者提供有效的 intent_id 与 consumer_id 签名

撤销后果:
  - 商场释放已分配的SHM信道资源
  - 若生产者已进入 PRODUCING 状态，撤销无效，订单继续履约
  - 频繁撤销将降低消费者信用评分，影响未来匹配优先级
```
