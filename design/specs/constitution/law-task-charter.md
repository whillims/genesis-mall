## 序言：任务即存在的痕迹

在微型商场的宇宙中，**任务（Task）** 不是简单的"待办事项"，而是**意图的物质化轨迹**。当消费者产生需求，当生产者响应召唤，当数据在SHM的绝对通道中开始流动——任务便从虚空中凝结为实体。

任务的本质是：**一段受控的交易序列，加上驾驭这段序列的逻辑意志**。没有任务，商场只是沉睡的硅基荒野；有了任务，商场才成为奔腾的意图之河。

本宪章确立任务的形而上学、所有权边界、生命周期法则与调度铁律。凡在商场中运行的实体，其存在必须以任务为凭证，其消亡必须以任务结算为句号。

## 第一章 任务本体论（Task Ontology）

### 第1条 任务定义

**任务（Task）** 是商场中最小可独立调度的意图单元，其数学表达为：

```
Task := { TransactionSequence[], ControlLogic, OwnerConsumer, OptionalProducerMask, TimeBudget, StateVector }
```

其中：
- **TransactionSequence[]**：一个或多个交易的时序排列，构成任务的骨骼；
- **ControlLogic**：控制交易流向、分支、合并与终止的函数集群，构成任务的神经；
- **OwnerConsumer**：任务的法定所有者，必须是商场中已注册的消费者实体；
- **OptionalProducerMask**：可选的生产者掩码，用于限定或筛选服务的供给方；
- **TimeBudget**：任务的时间预算契约，包含期望时间t₀与容忍上限t₁；
- **StateVector**：任务在SHM中的实时状态矢量，由商场原子操作维护。

### 第2条 任务与函数的关系

任务**高于函数**，但**由函数构成**。函数是蓝图中的静态基因，任务是基因在运行时的表达形态。

- 一个任务可以调用多个生产者的函数；
- 一个函数可以被多个任务并发调用；
- **函数无权知晓任务的全貌**，函数只负责在SHM中完成其被授权的数据变换；
- **任务有权监控所有其调用的函数状态**。

### 第3条 任务与蓝图的关系

蓝图是任务的**出生证明**，任务是蓝图的**运行实例**。

- 生产者通过AICoder审查的蓝图，定义了该生产者能生成的任务类型；
- 消费者发起任务时，实际上是在说："我接受某类蓝图所定义的交易契约，现在请求实例化"；
- 商场拒绝任何无蓝图支撑的任务——**没有蓝图的意图是非法的幽灵**。

## 第二章 任务所有权法则（Ownership Axioms）

### 第4条 消费者主权原则

**任务的所有权不可转让地归属于消费者（OwnerConsumer）**。

- 消费者可以是UI终端、文件句柄、数据库会话、外部网络端点或另一个Worker；
- 任务从诞生到销毁，其所有权矢量始终指向该消费者；
- 生产者、商场、AICoder均**不得篡夺、隐匿或转移**任务所有权；
- 任务产生的所有数据资产，其归属由任务所有权派生，遵循"谁发起，谁受益，谁负责"的三位一体原则。

### 第5条 生产者授权原则

生产者不拥有任务，但拥有**进入任务的授权（Authorization）**。

- 生产者通过向商场提交经AICoder签章的授权文件，获得响应特定任务类型的资格；
- 生产者对任务的介入是**被邀请的（Invited）**，而非主动的（Aggressive）；
- 若消费者未指定生产者（Open Call），则所有具备对应蓝图授权的生产者自动进入竞价或轮询池；
- 若消费者指定生产者（Directed Contract），则该生产者获得排他性响应权，同时承担时间契约中的刚性义务。

### 第6条 任务集合的封装权

消费者有权将其发起的多个任务封装为**任务集合（TaskSet）**。

- 任务集合是任务的超集，具备统一的状态观测接口；
- 任务集合可以嵌套，形成树状或图状的任务拓扑；
- 商场对任务集合的调度视为单一调度单元，但内部交易仍保持原子独立性；
- **任务集合的销毁遵循递归法则**：父节点销毁触发子节点级联销毁，除非子节点已被其他消费者接管。

## 第三章 任务生命周期铁律（Life Cycle Doctrine）

### 第7条 六态模型

任何任务在商场中必须严格经历以下六种状态，不允许跳过，不允许逆行：

| 状态 | 名称 | 定义 |
|------|------|------|
| S0 | **虚空（Void）** | 任务仅存在于消费者的意图中，尚未向商场注册 |
| S1 | **创建（Created）** | 消费者通过商场API提交任务描述，商场分配TaskID与SHM槽位 |
| S2 | **挂起（Pending）** | 任务等待生产者响应，或等待时间窗口开启 |
| S3 | **运行（Running）** | 至少一个生产者已认领任务，SHM中出现活跃数据流 |
| S4 | **结算（Settling）** | 交易序列完成，商场进行数据完整性校验与时间成本核算 |
| S5 | **终结（Terminated）** | 任务所有资源回收，SHM槽位释放，状态矢量归档 |

**状态跃迁必须由商场原子操作驱动**，任何外部实体不得直接修改状态寄存器。

### 第8条 创建法则

- 消费者创建任务时，必须提供**最小可执行描述（MED）**，包含：目标蓝图类型、输入数据摘要、时间预算；
- 商场在收到MED后，于SHM的任务控制区（Task Control Segment, TCS）写入任务元数据；
- TaskID采用**全局单调递增序列**，由商场主进程原子生成，确保全宇宙唯一性；
- **创建即承诺**：消费者一旦创建任务，即视为同意承担该任务可能产生的时间代价。

### 第9条 运行法则

- 任务进入Running态的充要条件是：存在至少一个已授权生产者，且该生产者向商场确认了认领信号；
- 运行期间，生产者通过SHM向消费者写入数据，**不得绕过SHM进行任何侧信道通信**；
- 商场以固定频率（如100Hz）扫描所有Running任务的状态矢量，检测死锁、饥饿与异常；
- 消费者有权在Running态发起**任务分裂（Task Split）**，将单一任务拆分为并行子任务，但分裂后的子任务各自独立结算。

### 第10条 终结法则

- 任务终结必须由商场发起，在确认以下全部条件后执行：
  1. 所有交易序列已标记完成；
  2. 消费者已发送或商场已代发消费确认（ACK）；
  3. 时间成本已核算并写入任务日志；
  4. 无活跃子任务挂起。
- 终结后，TaskID进入**历史命名空间（Historical Namespace）**，保留只读查询权，保留期为商场配置周期（默认7天）；
- 历史期结束后，TaskID释放回虚空，可被未来任务复用，但**历史记录永久不可篡改**。

## 第四章 任务调度与拥堵治理（Scheduling & Congestion）

### 第11条 SHM通道唯一性

**SHM是任务数据流动的唯一合法通道**。任何任务若试图通过管道、套接字、文件或隐秘内存进行数据交换，即构成**通道背叛罪**，商场有权立即终止涉事任务并吊销相关生产者授权。

### 第12条 非阻塞主进程原则

商场主进程（Mall Main）负责任务调度，但**绝不参与任务的数据搬运**。主进程通过操作SHM的元数据区完成调度决策，确保：

- 单个任务的阻塞不会冻结商场；
- 生产者或消费者的异常不会级联为商场崩溃；
- 调度决策延迟必须小于任务最小时间预算的1%。

### 第13条 拥堵与优先级

当多个任务竞争同一生产者或同一SHM带宽分区时，商场启动**拥堵仲裁协议**：

1. **时间契约优先**：时间预算更紧迫的任务获得更高调度权重；
2. **消费者等级**：长期履约记录良好的消费者享有隐性优先级加成；
3. **生产者负载均衡**：商场有权拒绝向已超载生产者分配新任务，即使消费者已指定；
4. **随机扰动**：为避免确定性饥饿，调度算法注入可控随机扰动（≤5%权重）。

## 第五章 违约与异常处理（Breach & Exception）

### 第14条 任务失效

以下情形导致任务强制失效（Invalidation）：

- 时间预算耗尽（t_current > t₁）；
- 生产者未在挂起期内认领（超时未响应）；
- 消费者主动发起取消指令且任务尚未进入Settling态；
- SHM通道完整性校验失败（数据哈希不匹配）；
- 生产者函数触发异常且未在蓝图规定的容错域内恢复。

### 第15条 失效任务的遗产

失效任务不直接销毁，而是进入**失效冻结态（Frozen Invalid）**，持续一个冷却周期（Cooldown）：

- 冷却期内，消费者可申请**任务尸检（Task Autopsy）**，由AICoder外置审计模块分析失效原因；
- 生产者可在冷却期内提交**抗辩声明（Defense Statement）**，解释失效缘由；
- 冷却期结束后，任务进入Terminated态，资源回收；
- **连续三次失效的生产者**，商场有权暂停其授权，移交AICoder重新审查蓝图。

### 第16条 任务间干扰禁令

任何任务不得探测、修改或延迟其他任务的状态矢量与数据区，除非该任务被显式授权为**监控者任务（Watcher Task）**。违反此禁令视为**任务间谍行为**，商场可立即隔离涉事实体。
