# 决策工具部署规范（Advisor Kernel Governance）

**版本**: v1.0
**日期**: 2026-05-12
**类型**: 架构宪法级规范
**关联**: 四域架构、三权分立、相产品分离、安全宪法v1.1~v1.3

---

## 核心结论

> 自动决策工具必须作为商场域后台分析进程池实现，通过 Worker 探针向 UI 推送结果；UI（JavaScript）只负责"相"的渲染，严禁承担任何分析计算。

---

## 一、禁止部署位置

### 1.1 禁止放在 UI（JavaScript）端

| 违例维度 | 具体风险 | 违反的既有铁律 |
|----------|----------|----------------|
| 数据边界 | 历史交易数据、审计日志是"产品"，若下载到前端则消费者域直接接触产品 | 四域架构：消费者域只应有"相" |
| 安全宪法 | 大量原始数据需经网络传输到浏览器，无法使用马赛克加密法保护 | v1.2 高速数据流体安全 |
| 计算权归属 | 数据挖掘、模式分析属于商场核心能力，若分散到前端则商场失去分析权统一性 | 三权分立：商场拥有匹配与评估权 |
| 防篡改 | JavaScript 运行在消费者本地环境，分析逻辑可被篡改、结果可被伪造 | 审计日志不可篡改原则 |
| 性能现实 | 千级任务历史数据在前端做模式挖掘，浏览器内存与算力无法支撑 | 工程可行性 |

**本质问题**: 把决策工具放在 UI，等于让消费者的浏览器直接"看见"并"操作"商场的核心数据资产，相与产品的哲学墙被击穿。

### 1.2 禁止作为生产者 Worker

| 违例维度 | 具体风险 | 违反的既有铁律 |
|----------|----------|----------------|
| 域隔离 | 生产者 Worker 只应产数据，不应访问其他生产者的历史记录或审计日志 | 四域架构：生产者域边界 |
| 权限越界 | 生产者 Worker 若具备跨任务分析能力，等于生产者可以"窥视"商场全局 | 三权分立：生产者与消费者隔离 |
| 单向性 | 生产者 Worker 的数据流应是单向输出，分析工具需要双向聚合查询 | 交易单向性原则 |

**本质问题**: 生产者 Worker 是"劳动力"，不是"管理者"；决策工具需要跨生产者、跨任务、跨消费者的全局视野。

## 二、正确架构位置：商场域后台分析进程池

│  │  │ 引擎        │ │ 引擎        │ │ 引擎        │   │    │

### 2.2 内核组件

| 组件 | 功能 | 数据来源 | 输出物 |
|------|------|----------|--------|
| `advisor_kernel_mine` | 历史模式挖掘 | 审计日志、交易完成记录 | 匹配模式、生产者排名 |
| `advisor_kernel_score` | 生产者动态评分 | 生产者历史交易指标 | 评分卡 JSON |
| `advisor_kernel_match` | 消费者需求匹配 | 消费者画像 + 生产者档案 | 推荐配置 |
| `advisor_kernel_report` | 报告生成 | 单任务完整生命周期数据 | 标准化报告 JSON |

### 2.3 与 UI 的交互协议

```
商场域分析完成 ──→ 结果摘要 ──→ VEC-PUB-ADVISO 矢量推送
                                          │
                                          ▼
                              消费者域 UI 通过 API 轮询获取
                                          │
                                          ▼
                              JavaScript 纯渲染（相操作）
```

**关键约束**:
- 推送到 UI 的数据必须是已脱敏、已格式化、已摘要的结果，而非原始交易记录
- UI JavaScript 禁止对推送数据进行任何计算、排序、过滤、聚合
- 若消费者需要调整分析维度，必须向商场域发送新的分析请求

## 三、与既有体系的兼容性

| 既有体系 | 兼容性验证 | 结果 |
|----------|-----------|------|
| 三权分立 | 消费者拥有"查看分析结果"的权利，商场拥有"生成分析结果"的权利，AICoder拥有"将结果编译为UI相"的权利 | ✅ |
| 四域架构 | 分析在商场域，呈现在消费者域，编译在AICoder域，生产在生产者域 | ✅ |
| 安全宪法 v1.1 | 分析结果经加密信道推送，公钥与来源绑定 | ✅ |
| 安全宪法 v1.2 | 若分析结果数据量大，采用马赛克加密法分片推送 | ✅ |
| 安全宪法 v1.3 | 沙箱调试时，分析结果明文推送；生产环境强制加密 | ✅ |
| 相产品分离 | 分析引擎处理"产品"（原始数据），UI只处理"相"（呈现） | ✅ |
| SHM内存宪法 | 分析引擎通过商场域内部机制访问数据，不直接操作SHM | ✅ |
| 任务治理体系 | 交易监督者通过治理工具调用决策工具出具报告 | ✅ |

## 四、例外场景：前端轻量相操作

唯一允许 UI JavaScript 做"计算"的场景：

| 场景 | 允许的计算类型 | 禁止的计算类型 |
|------|---------------|---------------|
| 图表交互 | 鼠标悬停坐标映射、局部缩放、颜色切换 | 数据重排序、重新聚合、趋势预测 |
| 报告排版 | 分页计算、字体适配、布局响应 | 指标重算、评分重算 |
| 实时看板 | 接收推送数据的直接渲染（无缓冲计算） | 多帧数据拼接后的衍生计算 |

**铁律**: 凡涉及数据意义生成的计算必须在商场域；凡仅涉及像素位置生成的计算可在UI域。

---

## 五、铁律总结

> 决策工具 = 商场域分析进程池（内核）+ 矢量推送（VEC-PUB-ADVISO）+ UI纯渲染（JavaScript相操作）

1. **数据不落地**: 原始交易数据与审计日志永不出商场域
2. **计算不分散**: 分析逻辑统一维护，版本一致，结果可信
3. **相不越权**: UI只负责"好看"，不负责"看懂"
4. **安全不妥协**: 全链路符合马赛克加密法与沙箱/生产隔离铁律
