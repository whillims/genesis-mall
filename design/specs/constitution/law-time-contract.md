# 时间契约纲领（Time Contract Manifesto）
**版本**：v1.0 纲领性文档  
**编号**：LAW-TIME-0001  
**地位**：商场经济体系的基石法则，定义时间作为通用等价物的兑换规则  
**哲学基础**：时间在商场中不是背景噪音，而是**最硬的通货**

---

## 序言：时间的炼金术

在微型商场中，一切算力、数据、带宽最终都可以折算为时间。生产者消耗时间制造产品，消费者消耗时间等待产品，商场消耗时间维持秩序。**时间是我们唯一不能伪造的资源**。

本纲领确立时间成本的度量衡、时间膨胀的数学模型、代价的随机性本质，以及时间违约的仲裁机制。凡在商场中缔结的任务契约，其底层都必须锚定在本纲领的时间坐标系上。

---

## 第一章 时间成本原理（Principles of Temporal Cost）

### 第1条 时间的双重标价

每个任务携带两个时间常数：

- **t₀（期望时间/基准时间）**：在理想条件下，从任务创建到终结的预期耗时。由消费者设定，生产者认可，商场备案；
- **t₁（容忍上限/熔断时间）**：消费者能接受的绝对最大等待时间。超过t₁，任务自动触发失效协议。

关系约束：**0 < t₀ ≤ t₁ < ∞**。t₀ = t₁ 的情况仅在紧急任务中允许，且消费者必须明示"零容差"，同时承担加倍的时间代价。

### 第2条 实际时间 t_actual

任务运行过程中，商场持续记录**实际流逝时间**：

```
t_actual := t_settling - t_created
```

其中，t_settling 为任务进入Settling态的时间戳。若任务失效，则以失效时刻为准。

### 第3条 时间膨胀系数

定义**时间膨胀系数（Dilation Factor）** δ：

```
δ = t_actual / t₀
```

- 当 δ ∈ (0, 1]：任务提前或准时完成，消费者获得**时间盈余信用**；
- 当 δ ∈ (1, t₁/t₀]：任务延迟但在容忍范围内，进入**正常代价区间**；
- 当 δ > t₁/t₀：任务超时，触发**熔断与违约程序**。

商场定期发布全局平均膨胀系数 δ_mall，作为市场拥堵指数的宏观指标。

## 第二章 代价随机性法则（The Law of Stochastic Cost）

### 第4条 拥堵即常态

商场拒绝承诺"确定性延迟"。**拥堵是分布式系统的固有属性**，不是故障。因此：

- 即使消费者指定了特定生产者，实际完成时间仍受该生产者当前负载、SHM带宽竞争、前置任务排队等因素影响；
- **t_actual 是一个随机变量**，而非固定值。其分布由商场运行时环境决定。

### 第5条 运气成分宣言

时间代价中必然包含**运气成分（Luck Component）**。

- 消费者可能在低负载瞬间提交任务，获得 δ < 1 的超额回报；
- 消费者也可能在峰值拥堵时刻提交任务，面临 δ 接近 t₁/t₀ 的极限压力；
- **这种随机性不是不公，而是商场经济的心跳**。它防止了确定性套利，维持了生产者的多样性与系统的鲁棒性。

### 第6条 代价计算模型

消费者为任务支付的时间代价（Cost）按以下模型计算：

```
Cost = BaseCost + CongestionPremium + LuckAdjustment

BaseCost = k₀ × t₀          （基准代价，与期望时间成正比）
CongestionPremium = k₁ × (t_actual - t₀)  （拥堵溢价，仅当延迟时征收）
LuckAdjustment = ±k₂ × Rand(0, σ)  （运气调整项，可正可负，均值为0）
```

其中 k₀, k₁, k₂ 为商场全局系数，σ 为当前时段的拥堵标准差。

**关键原则**：消费者支付的总代价**不以 t_actual 为唯一基准**，而是以 t₀ 为锚点，以 (t_actual - t₀) 为溢价。这意味着：

- 即使任务延迟，只要延迟在预期内，消费者仍主要为自己最初的期望买单；
- 严重延迟时，拥堵溢价呈线性甚至超线性增长，形成对生产者的经济惩戒。

## 第三章 消费者代价义务（Consumer Obligations）

### 第7条 指定生产者的代价承诺

当消费者在任务中**显式指定（Directed）**某一生产者时，即视为签订了一份**定向时间契约**：

- 消费者承认该生产者可能处于高负载状态；
- 消费者同意接受因此产生的额外时间代价；
- 消费者**不得因定向导致的延迟而发起无理抗辩**，除非延迟超过t₁触发熔断。

### 第8条 不指定生产者的自由与代价

当消费者**不指定生产者（Open Call）**时：

- 商场将任务投入公共池，由可用生产者竞争响应；
- 消费者通常获得更短的平均等待时间（市场选择效应）；
- 但消费者**丧失对生产者的选择权**，必须接受第一个合格响应者的服务；
- 若消费者对响应者的质量不满意，可在任务创建时附加**质量门槛（Quality Gate）**，但这会提高BaseCost。

### 第9条 时间预付费与后付费

商场支持两种时间代价结算模式：

- **预付费（Prepaid）**：消费者在创建任务时锁定最大可能代价（基于t₁），任务终结后多退少补。适用于高确定性场景；
- **后付费（Postpaid）**：消费者在任务终结后按实际代价支付。适用于探索性场景，但消费者必须拥有足够的信用额度。

**默认模式为后付费**，因为预付费的锁仓行为会降低商场流动性。

## 第四章 生产者时间责任（Producer Temporal Liability）

### 第10条 时间预算刚性

生产者在认领任务时，必须向商场声明其**预估完成时间（ETC）**。ETC必须满足：

```
ETC ≤ t₁ - t_current_elapsed
```

若生产者明知不可为而虚报ETC，构成**时间欺诈**，商场有权：
- 立即将该任务重新投入公共池；
- 对生产者记一次时间失信记录；
- 累计三次时间失信，暂停该生产者授权30秒至300秒（指数退避）。

### 第11条 延迟预警义务

生产者在任务运行期间，若发现无法在原定ETC内完成，必须**提前向商场发出延迟预警（Delay Warning）**：

- 预警必须包含新的ETC' 和延迟原因编码；
- 商场收到预警后，有权将任务**热迁移（Hot Migrate）**至其他生产者，原生产者保留部分基础代价份额；
- 若生产者未预警而直接超时，视为**时间违约**，丧失该任务全部代价份额，并承担违约金。

### 第12条 生产者的时间信用体系

每个生产者拥有一个**时间信用分（Temporal Credit Score, TCS）**：

- TCS ∈ [0, 1000]，初始值为500；
- 准时履约 +10 分，提前履约 +15 分，轻微延迟（δ < 1.2）-5 分，严重违约 -50 分；
- TCS > 800 的生产者获得"时间贵族"称号，享有任务优先推送权；
- TCS < 200 的生产者进入"时间观察名单"，商场限制其同时处理的任务数 ≤ 1。

## 第五章 时间仲裁与补偿（Temporal Arbitration）

### 第13条 时间争议的定义

以下情形构成时间争议：

- 消费者认为t_actual严重偏离合理预期，但尚未触发t₁熔断；
- 生产者认为延迟源于消费者提供的输入数据过大或格式违规；
- 多方生产者协作任务中，某一方导致级联延迟，责任归属不清。

### 第14条 仲裁流程

1. **申诉期**：争议发生后，涉事方须在任务终结后60秒内提交时间申诉（Temporal Appeal）；
2. **冻结期**：商场冻结该任务的全部代价分配，持续一个仲裁周期（默认10秒）；
3. **举证期**：各方通过SHM日志区提交证据，包括时间戳、数据量、函数调用序列；
4. **裁决期**：商场内置的**轻量级仲裁器（Arbiter Function）**根据日志自动裁决。若自动裁决置信度 < 90%，则移交外置AICoder进行深度审计；
5. **执行期**：裁决结果写入任务日志，代价按裁决比例重新分配。

### 第15条 补偿规则

- 若仲裁认定生产者全责：生产者向消费者返还已收代价，并支付**等额时间罚金**。罚金注入商场公共时间池，用于奖励高信用生产者；
- 若仲裁认定消费者全责（如输入数据违规）：消费者承担全部代价，并支付仲裁费用；
- 若认定为不可抗力（SHM通道瞬时故障、商场主进程调度抖动）：代价由商场公共时间池承担，双方免责。

### 第16条 速率调节免责

商场基于资源管理需要，对Worker实施产出速度调节（节流/限流/加速）时，适用以下免责条款：

1. **调节的合法性**: 速率调节属于商场调度权的自然延伸，商场有权根据SHM带宽利用率、任务优先级、系统负载等因素调节Worker产出速率。

2. **调节的告知义务**: 商场必须在调节发生时向受影响的生产者发布调节事件（EVENT类型），包含调节原因、幅度、预期持续时间。

3. **时间代价的重新计算**: 因速率调节导致的t_actual增加，不计入生产者的时间失信记录，不影响生产者的时间信用分（TCS）。调节期间的代价按以下公式重新计算：

```
Cost_adjusted = BaseCost + (CongestionPremium × rate_factor)

其中 rate_factor = actual_output_rate / nominal_output_rate
```

4. **紧急调节的优先权**: 当SHM带宽利用率超过95%或P0通道出现拥堵时，商场有权不经预告立即实施紧急节流，事后补发调节事件。

5. **调节的边界**: 速率调节不得将output_rate降至0以下，不得导致已封印产品的完整性受损，不得绕过掩码匹配机制。

## 附则

- 本纲领中的时间单位为**商场原子时（Mall Atomic Time, MAT）**，1 MAT = 1毫秒（可配置）；
- 所有时间戳必须以商场主进程的单调时钟（Monotonic Clock）为基准，禁止使用系统 wall-clock 以防闰秒与校时干扰；
- 本纲领与《商场任务宪章》具有同等法律效力，冲突条款以**时间契约优先**（因为时间是更底层的约束）。

**时间不会背叛商场，但商场必须诚实地对待时间。**
