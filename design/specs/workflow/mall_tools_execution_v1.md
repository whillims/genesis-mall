# 任务执行与监督工具设计 v1.0

> **阶段覆盖**：任务生命周期第三阶段（执行）与第四阶段（监督）
> **核心目标**：让消费者在执行过程中保持"看得见、摸得着、停得了"的掌控感

---

## 一、任务执行工具族（Execution）

### 1.1 实时状态监控台

**功能**：显示生产者心跳、数据吞吐率、错误计数。

**监控指标**：
| 指标 | 来源 | 刷新频率 | 告警阈值 |
|------|------|---------|---------|
| 生产者心跳 | 生产者定时心跳包 | 1Hz | 3秒未收到即标红 |
| 数据吞吐率 | SHM写入速率统计 | 实时 | 低于契约值90%变黄 |
| 错误计数 | 生产者自检 + 商场校验 | 实时 | >0 即记录 |
| 任务进度 | 已完成的子任务数/总数 | 1Hz | 无 |
| 资源占用 | CPU/内存/SHM使用量 | 5Hz | 超过契约上限告警 |

**UI呈现**：
- 仪表盘布局（类似飞机驾驶舱，关键指标大而醒目）
- 每个生产者一个独立卡片，显示其专属状态
- 颜色编码：绿（正常）/ 黄（警告）/ 红（异常）/ 灰（离线）

**载体**：Worker采集数据 → UI渲染（通过加密通道）。

---

### 1.2 参数动态调节器

**功能**：消费者实时调整生产者速度、采样率等参数。

**设计原则（援引IO原则）**：
- **单向性**：调节指令只能从消费者/UI → Worker → 生产者，不可反向
- **时效性**：调节指令必须在IO帧间隙发送，不得切割正在传输的数据包
- **独立性**：每个调节指令是原子操作，不依赖前序指令状态

**实现架构**：
```
消费者UI (旋钮/输入框)
    ↓ [加密指令通道]
调节指令Worker (验证指令合法性：是否在安全边界内？)
    ↓ [SHM矢量管理]
生产者控制接口 (应用新参数)
    ↓
下一帧数据按新参数生成
```

**调节类型**：
| 类型 | 示例 | 安全边界 |
|------|------|---------|
| 连续值 | 激励功率-10dB → 0dB | 不得超过生产者声明的最大值 |
| 离散值 | 采样率1MHz/5MHz/10MHz | 仅允许契约中约定的档位 |
| 布尔值 | 触发模式：自动/单次 | 切换时不得丢失已采集数据 |
| 枚举值 | 测量模式：CW/脉冲/扫频 | 模式切换需生产者确认就绪 |

**反馈机制**：
- UI显示"已发送" → "生产者确认" → "已生效"三态进度
- 若5秒内未收到确认，自动回滚UI显示并告警

**安全铁律**：
- 沙箱调试期：调节器全透明，无加密，便于调试
- 保密试运行期：调节指令启用端到端加密 + 来源绑定
- 正式归档期：调节历史纳入审计日志

### 1.3 IO流检视器

**功能**：可视化数据流向，标记阻塞点与丢包点。

**呈现方式**：
- 拓扑图：生产者 → SHM → 消费者UI 的数据管道
- 流速动画：数据包像水流一样在管道中移动
- 阻塞标记：当某段管道流速骤降，高亮显示并标注原因

**诊断信息**：
- 端到端延迟（生产者生成 → UI呈现）
- 各段管道的带宽利用率
- 丢包位置与丢包率
- SHM缓冲区占用率（防止溢出）

**载体**：Worker实时计算流统计 → UI渲染拓扑图。

---

### 1.4 紧急制动阀

**功能**：消费者一键中断任务（最高优先级指令）。

**设计隐喻**：物理世界的"红色蘑菇头按钮"——醒目、大、不可误触但可快速触发。

**指令优先级**：
```
紧急制动 > 参数调节 > 正常数据流 > 心跳包
```

**执行流程**：
```
消费者点击紧急制动
    ↓
UI立即本地响应（按钮变色、锁定其他操作）
    ↓
发送制动指令（最高优先级通道，绕过正常队列）
    ↓
Worker接收 → 立即向所有相关生产者发送停机信号
    ↓
生产者进入安全停机状态（如信号源关闭输出、功率计断开激励）
    ↓
UI显示"已制动"，解锁"恢复"与"终止"选项
```

**二次确认**：
- 首次点击：进入"预制动"状态，3秒倒计时
- 倒计时内可取消
- 倒计时结束或再次点击：正式制动

**审计**：制动事件永久记录，包含触发时间、消费者身份、任务状态。

## 二、任务监督工具族（Oversight）

### 2.1 交易审计日志

**功能**：记录每一笔数据交换的时间戳、签名、完整性哈希。

**日志条目结构**：
```json
{
  "timestamp": "2026-05-12T17:09:00.000Z",
  "sequence_id": 1024,
  "producer_id": "sig_gen_01",
  "consumer_id": "user_42",
  "data_hash": "sha256:abc123...",
  "signature": "...",
  "integrity_check": "PASS",
  "mall_attestation": "..."
}
```

**查询能力**：
- 按时间范围查询
- 按生产者/消费者查询
- 按完整性状态查询（PASS/FAIL）
- 导出为CSV/PDF供外部审计

**载体**：Worker写入只追加日志存储，任何人（包括商场管理员）不可篡改。

---

### 2.2 异常告警器

**功能**：当生产者偏离契约参数时触发分级告警。

**告警级别**：
| 级别 | 触发条件 | 消费者可见性 | 自动动作 |
|------|---------|-------------|---------|
| **提示** | 数据速率低于预期10% | UI状态栏变黄 | 无 |
| **警告** | 功率计返回异常码/超时 | UI弹窗 + 声音 | 暂停数据采集，等待消费者决策 |
| **严重** | 信号源失锁/功率计离线 | UI全屏红警 + 震动 | 触发紧急制动阀，自动切断激励 |
| **灾难** | SHM数据污染/签名失效 | 所有UI实例同步告警 | 商场强制隔离该生产者，启动审计 |

**关键设计**：
- 告警器作为Worker运行，但**所有升级动作必须经过消费者确认**（除非是灾难级自动保护）
- 这符合"工具提供能力，人类掌握决策权"的铁律

**告警抑制**：
- 消费者可设置"已知异常白名单"（如被测件固有滞后导致的速率波动）
- 白名单内的异常不触发告警，但仍记录日志

---

### 2.3 质量抽检器

**功能**：按消费者预设的规则对输出数据进行抽样验证。

**抽检规则**：
- 每N个数据包抽检1个
- 关键节点（如频率切换点）强制抽检
- 数据值范围校验（如功率应在-60dBm至+20dBm之间）
- 时序一致性校验（时间戳单调递增）

**结果呈现**：
- 抽检通过率实时显示
- 失败样本高亮，附带预期值与实际值对比
- 趋势图：近100次抽检的通过率曲线

**载体**：Worker执行抽检逻辑 → UI呈现结果。

---

### 2.4 进度推演仪

**功能**：基于当前速率预测完成时间，识别延期风险。

**推演模型**：
```
剩余工作量 / 当前平均速率 = 预估剩余时间
预估剩余时间 + 已用时间 = 预估总时间
```

**不确定性处理**：
- 当被测件存在滞后，自动加入缓冲时间
- 当生产者速率波动大，给出乐观/悲观区间

**风险识别**：
- 若预估总时间 > 契约最大时长 × 80%，触发"延期风险"提示
- 若预估总时间 > 契约最大时长，触发"即将违约"警告

## 三、执行与监督阶段的决策权归属

| 决策点 | 决策主体 | 工具角色 |
|--------|---------|---------|
| 参数调节 | 消费者 | 调节器提供调节能力 |
| 紧急制动 | 消费者 | 制动阀提供中断能力 |
| 告警响应 | 消费者 | 告警器提供信息与建议 |
| 质量判定 | 消费者 | 抽检器提供数据证据 |
| 灾难级隔离 | 商场（自动） | 告警器触发保护机制 |
