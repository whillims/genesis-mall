# IO调试细则（IO Debug Protocol）

> **声明**: 本文档内容通过引导AI自动生成，仅供设计参考与学术交流。

**版本**: v1.1
**编号**: SPEC-IO-DEBUG-0001
**地位**: IO操作从蓝图设计到系统挂接的强制性调试流程规范
**核心原则**: **先独立验证，后系统挂接**——任何IO操作必须在独立进程中完成测试验证，通过后再与商场系统挂接联试
**新增规则**: IO Worker 必须具有全局唯一性标识，确保在任何并发、克隆、分布式场景下的可追溯性

---

## 序言：IO调试的必要性

IO操作是商场系统中唯一与外部物理世界交互的通道。IO的不可控性（设备延迟、协议错误、硬件故障、驱动异常）使其成为系统稳定性的最大威胁源。

本细则确立的铁律是：**IO代码在进入商场之前，必须先证明自己在隔离环境中能正确工作**。这类似于航天工程中的"组件级测试→系统集成测试"范式——绝不在系统级调试中排查本应在组件级解决的问题。

## 第一章 两阶段调试模型

### 第1条 阶段定义

IO调试分为两个严格有序的阶段：

```
┌─────────────────────────────────────────────────────────────────┐
│                      IO调试两阶段模型                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────────────────┐      ┌──────────────────────┐        │
│  │   阶段一：独立验证     │ ──→  │   阶段二：系统挂接     │        │
│  │  (Sandbox Verify)    │      │  (System Integration) │        │
│  │                      │      │                      │        │
│  │  · 独立进程           │      │  · 商场进程内          │        │
│  │  · 合成数据/真实设备   │      │  · SHM矢量交互        │        │
│  │  · 单函数级测试        │      │  · 蓝图全链路测试      │        │
│  │  · 无需商场依赖       │      │  · 回归验证           │        │
│  └──────────────────────┘      └──────────────────────┘        │
│           │                              │                     │
│           ▼                              ▼                     │
│      验证通过证书                   联试通过证书                  │
│      (Verify Pass)               (Integration Pass)            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 第2条 阶段一：独立进程验证（Sandbox Verify）

**目标**: 在独立进程中，使用合成数据或真实设备，验证IO函数的正确性。

**环境要求**:
- 独立Python进程，不依赖商场主进程
- 不依赖SHM矢量空间（使用内存字典模拟）
- 不依赖商场调度器、注册表、心跳等服务
- 可选接入真实IO设备或使用合成数据引擎

**验证范围**:
- 函数签名正确性（输入输出类型、返回值结构）
- 正常路径（标准输入→预期输出）
- 边界路径（空输入、最大长度、特殊字符）
- 异常路径（设备不存在、超时、权限不足、协议错误）
- 性能基线（延迟、吞吐量、资源占用）

**通过标准**:
- 所有测试用例通过（覆盖率 > 90%）
- 无内存泄漏
- 无僵尸/孤儿进程
- 性能基线达标

### 第3条 阶段二：系统挂接联试（System Integration）

**目标**: 将已通过独立验证的IO函数挂接到商场系统中，验证与SHM矢量、调度器、其他Worker的协同工作。

**环境要求**:
- 商场主进程运行中
- SHM矢量空间可用
- 相关Worker已注册（生产者/消费者）
- IO管理Worker（BP-0046）已加载

**联试范围**:
- SHM矢量读写正确性
- 与生产者/消费者的数据流转
- 超时与错误恢复（商场调度器介入）
- 路径分级（P0-P3）下的IO优先级
- 产出速率调节对IO的影响
- 长时间运行稳定性

**通过标准**:
- 端到端数据链路通畅
- 错误可被商场异常体系正确捕获
- 审计日志完整记录
- 回归测试通过（阶段一的测试用例在系统环境中仍然通过）

### 第4条 阶段门禁

| 门禁 | 条件 | 拒绝动作 |
|------|------|----------|
| V→I 门禁 | 阶段一验证通过证书 | 禁止进入阶段二 |
| I→P 门禁 | 阶段二联试通过证书 | 禁止提交授权文件 |
| P→D 门禁 | 七维审查 + 授权文件验证 | 禁止载入算力池 |

**铁律**: 未获得阶段一验证通过证书的IO代码，禁止进入阶段二。未获得阶段二联试通过证书的IO代码，禁止提交AICoder审查。

## 第二章 独立验证流程

### 第5条 验证环境搭建

```
io-debug-sandbox/
├── config/
│   └── io-debug-manifest.json      # 沙箱配置清单
├── workers/
│   ├── {blueprint_name}_io.py      # 待验证的IO函数（从蓝图提取）
│   └── synthetic_io_engine.py      # 合成数据引擎
├── tests/
│   └── test_{blueprint_name}.py    # 验收测试
└── docs/
    └── README.md                   # 验证报告
```

### 第6条 验证步骤

#### 6.1 从蓝图提取IO函数

根据蓝图设计，将IO相关函数提取为独立Python模块：

1. 读取蓝图中的函数签名和行为契约
2. 实现纯函数级Python代码（遵循函数范式宪章）
3. 用内存字典替代SHM交互（`ctx["shm_store"] = {}`）
4. 用合成数据替代真实设备输入

#### 6.2 编写验收测试

测试必须覆盖以下类别：

| 类别 | 数量要求 | 覆盖点 |
|------|----------|--------|
| 正常路径 | ≥ 5 | 标准输入→预期输出 |
| 边界路径 | ≥ 3 | 空输入、最大长度、零值、极值 |
| 异常路径 | ≥ 5 | 设备不存在、超时、权限不足、协议错误、数据截断 |
| 性能基线 | ≥ 2 | 延迟上限、吞吐量下限 |
| 资源安全 | ≥ 2 | 内存泄漏检测、进程回收验证 |

#### 6.3 执行验证

```bash
cd io-debug-sandbox/
python -m pytest tests/test_{blueprint_name}.py -v --tb=short
```

#### 6.4 生成验证证书

验证通过后，生成验证报告（写入 `docs/README.md`）：

```yaml
verify_certificate:
  blueprint_id: BP-XXXX
  function_name: xxx_io_func
  verify_date: YYYY-MM-DD
  test_count: N
  pass_count: N
  coverage: 0.XX
  performance_baseline:
    latency_ms: X.X
    throughput_ops_sec: X.X
  resource_check:
    memory_leak: false
    orphan_process: false
  verdict: PASS / FAIL
```

## 第三章 系统挂接联试流程

### 第7条 挂接前置条件

进入阶段二前，必须确认以下条件全部满足：

| # | 条件 | 验证方式 |
|---|------|----------|
| 1 | 阶段一验证证书存在且verdict=PASS | 检查verify_certificate |
| 2 | 商场主进程运行中 | `mall_ping()` 返回ok |
| 3 | SHM矢量空间可用 | `shm_health_check()` 返回ok |
| 4 | IO管理Worker（BP-0046）已加载 | `registry_query("io_manager")` 返回registered |
| 5 | 相关生产者/消费者Worker已注册 | `registry_query()` 确认 |
| 6 | 合成数据引擎或真实设备就绪 | `io_device_probe()` 返回ready |

### 第8条 挂接步骤

#### 8.1 SHM适配

将独立验证中的内存字典替换为真实SHM交互：

```python
# 阶段一（独立验证）
ctx = {"shm_store": {}}  # 内存字典模拟

# 阶段二（系统挂接）
ctx = {"shm_handle": real_shm_handle, "shm_config": shm_config}  # 真实SHM
```

#### 8.2 端到端数据链路测试

```
生产者Worker ──[SHM写入]──→ IO函数 ──[SHM写入]──→ 消费者Worker
                                    │
                              [设备IO操作]
                                    │
                              真实设备/合成数据
```

测试项：
- 生产者写入SHM → IO函数正确读取
- IO函数执行设备操作 → 结果写入SHM
- 消费者从SHM读取 → 数据完整性和时效性

#### 8.3 错误恢复测试

| 场景 | 预期行为 |
|------|----------|
| 设备突然断开 | IO函数返回错误，商场异常体系捕获，审计日志记录 |
| IO操作超时 | IO管理Worker触发超时，子进程回收，通知调用者 |
| SHM写入失败 | IO函数返回错误，不产生副作用 |
| 调度器暂停IO Worker | 产出速率调节生效，IO操作排队等待 |

#### 8.4 回归验证

在系统环境中重新运行阶段一的全部测试用例，确认：
- 所有测试仍然通过（环境切换未引入回归）
- 性能基线在可接受范围内（系统开销 < 20%）

### 第9条 联试通过证书

联试通过后，生成联试报告：

```yaml
integration_certificate:
  blueprint_id: BP-XXXX
  function_name: xxx_io_func
  integration_date: YYYY-MM-DD
  e2e_test_count: N
  e2e_pass_count: N
  error_recovery_test_count: N
  regression_test_count: N
  regression_pass_count: N
  performance_overhead: 0.XX
  verdict: PASS / FAIL
```

## 第四章 IO调试安全约束

### 第10条 隔离要求

| IO类型 | 阶段一隔离 | 阶段二隔离 |
|--------|-----------|-----------|
| DISK_READ/WRITE | 可选（小文件） | 商场SHM域内 |
| NETWORK_RX | **必须进程隔离** | IO管理Worker子进程 |
| NETWORK_TX | 可选（线程隔离） | IO管理Worker子进程 |
| EXTERNAL_PROC | **必须进程隔离** | IO管理Worker子进程 |
| DEVICE_IO（串口/USB/GPIO等） | **必须进程隔离** | IO管理Worker子进程 |

### 第11条 超时控制

| 阶段 | 默认超时 | 最大超时 | 超时处置 |
|------|----------|----------|----------|
| 阶段一（单函数） | 5秒 | 30秒 | 终止测试，标记FAIL |
| 阶段二（端到端） | 10秒 | 60秒 | IO管理Worker回收子进程 |
| 阶段二（长时间稳定性） | 1小时 | 4小时 | 商场调度器介入 |

### 第12条 资源限制

| 资源 | 阶段一限制 | 阶段二限制 |
|------|-----------|-----------|
| 内存 | 128MB | 512MB |
| CPU | 50% | 50% |
| 子进程数 | 4 | 16 |
| 并发IO句柄 | 16 | 256 |

### 第13条 合成数据引擎

阶段一必须使用合成数据引擎替代真实设备，确保测试的可重复性：

| 合成函数 | 用途 | 适用IO类型 |
|----------|------|-----------|
| `synth_waveform_sine()` | 正弦波生成 | 音频、ADC、频谱仪 |
| `synth_waveform_square()` | 方波生成 | GPIO、数字信号 |
| `synth_digital_sequence()` | 数字序列 | 串口、SPI、I2C |
| `synth_serial_frame()` | UART帧生成 | 串口通信 |
| `synth_can_frame()` | CAN帧生成 | CAN总线 |
| `synth_modbus_rtu_frame()` | Modbus帧生成 | 工业总线 |
| `synth_spectrum_noise()` | 带噪声频谱 | 频谱分析 |
| `synth_analog_ramp()` | 模拟斜坡 | 传感器模拟 |

## 第六章 IO Worker 唯一性标识规范

### 第17条 唯一性标识铁律

**铁律**: 所有 IO Worker 实例必须具有全局唯一性标识（IO-Worker-UID），该标识贯穿 Worker 整个生命周期，用于：
- 进程追踪与调试
- 资源归属审计
- 并发冲突检测
- 分布式场景下的节点标识

### 第18条 标识格式规范

IO Worker 唯一性标识格式为：
```
IO-WORKER-{TYPE}-{TIMESTAMP}-{RANDOM}-{SEQUENCE}
```

| 字段 | 说明 | 示例 |
|------|------|------|
| `IO-WORKER` | 固定前缀 | `IO-WORKER` |
| `{TYPE}` | IO操作类型 | `NETWORK_RX`, `DISK_READ`, `DEVICE_IO` |
| `{TIMESTAMP}` | 13位毫秒时间戳 | `1747123456789` |
| `{RANDOM}` | 8位随机十六进制 | `A3F2D1C9` |
| `{SEQUENCE}` | 4位序号（可选，用于克隆场景） | `0001` |

**示例完整标识**:
```
IO-WORKER-NETWORK_RX-1747123456789-A3F2D1C9-0001
```

### 第19条 标识生成规则

1. **初始生成**: IO Worker 实例化时，由 `io_manager_init()` 生成基础标识
2. **克隆继承**: 克隆 Worker 时，继承基础标识的前三个字段，在第四字段添加序号
3. **时间单调**: 同一 Worker 的多个实例，时间戳必须严格单调递增
4. **随机防碰撞**: 随机字段使用 `os.urandom(4).hex()` 生成，确保并发无碰撞

### 第20条 标识存储与传播

| 存储位置 | 用途 | 访问权限 |
|----------|------|----------|
| IO句柄结构 (`IOHandle`) | 运行时追踪 | IO管理器内部 |
| SHM矢量 (`vec/worker`) | 跨进程共享 | 调度器、审计模块 |
| 审计日志 | 持久化记录 | 审计模块写入 |

### 第21条 标识验证机制

阶段一（独立验证）必须验证：
- 标识格式符合规范
- 同一 Worker 的多个实例，标识互不冲突
- 克隆场景下序号字段正确递增

阶段二（系统挂接）必须验证：
- 标识在 SHM 中正确传播
- 调度器可正确识别 Worker 标识
- 审计日志完整记录标识流转

### 第22条 唯一性标识错误处理

| 错误场景 | 错误码 | 处置动作 |
|----------|--------|----------|
| 标识格式非法 | `IO_UID_INVALID` | 拒绝实例化 |
| 标识冲突检测 | `IO_UID_COLLISION` | 重新生成并告警 |
| 时间戳回退 | `IO_UID_TIME_REGRESS` | 拒绝并记录安全事件 |
| SHM写入失败 | `IO_UID_SHM_WRITE_FAIL` | 实例化失败，返回错误 |

### 第23条 唯一性标识安全约束

- 标识不可伪造：基于时间戳+随机数生成，不可预测
- 标识不可重放：每次实例化必须重新生成
- 标识不可篡改：SHM中标识字段只写不覆盖
- 标识不可伪造：拒绝无标识或伪造标识的 Worker 接入调度器
