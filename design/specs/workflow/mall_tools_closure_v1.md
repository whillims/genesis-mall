## 一、任务完结工具族

### 1.1 成果验收面板

**功能**：消费者对输出数据进行确认 / 驳回 / 部分接受。

**验收维度**：
| 维度 | 消费者操作 | 系统记录 |
|------|-----------|---------|
| **完整性** | 确认数据量是否达到契约要求 | 实际数据点数 vs 契约点数 |
| **正确性** | 抽查关键数据点，标记异常 | 验收标记哈希 |
| **时效性** | 确认是否在契约时间内完成 | 实际耗时 vs 契约时限 |
| **格式合规** | 确认数据格式符合蓝图要求 | 格式校验报告 |

**验收状态**：
- **完全接受**：任务进入归档流程，生产者获得完整信誉积分
- **部分接受**：消费者标注接受范围与驳回原因，生产者获得部分积分
- **完全驳回**：消费者详细说明驳回原因，生产者不得分，触发争议处理

**UI设计**：
- 左侧：数据总览（总量、异常点数量、关键指标统计）
- 右侧：数据预览（可缩放、可标记）
- 底部：验收操作区（接受/驳回按钮 + 原因文本框）

**禁止**：
- 禁止消费者在未查看数据的情况下一键验收（防止误操作）
- 禁止系统默认"自动验收"（人类决策权铁律）

### 1.2 数据归档打包器

**功能**：将任务全过程数据打包存档。

**归档包结构**：
```
task_archive_{contract_id}.tar
├── manifest.json          # 归档清单与完整性哈希
├── data/
│   ├── raw/                 # 原始生产者输出数据
│   ├── processed/           # 商场处理后的数据（如有）
│   └── metadata/            # 数据描述信息
├── logs/
│   ├── audit_log/           # 交易审计日志
│   ├── control_log/         # 参数调节历史
│   └── alarm_log/           # 异常告警记录
├── contracts/
│   ├── original_contract.md # 原始契约（人类可读）
│   └── signed_contract.json # 签名后的契约
├── blueprints/
│   └── consumer_blueprint.json # 消费者原始蓝图
└── signatures/
    ├── consumer_approval.sig
    ├── mall_approval.sig
    └── data_integrity.sig
```

**完整性保障**：
- 每个文件有独立SHA-256哈希
- 整个归档包有顶层签名
- 归档包写入WORM存储（Write Once Read Many），不可篡改

**消费者权利**：
- 可随时下载自己的归档包
- 可要求商场删除归档（但审计日志保留最低期限）
- 可将归档包迁移至其他商场（蓝图自由迁移权）

### 1.3 生产者评价器

**功能**：消费者对生产者表现打分，反馈至商场信誉系统。

**评价维度**：
| 维度 | 权重 | 说明 |
|------|------|------|
| **稳定性** | 30% | 任务过程中是否频繁异常 |
| **准确性** | 30% | 输出数据是否符合预期精度 |
| **时效性** | 20% | 是否按时完成 |
| **协作性** | 10% | 对参数调节的响应速度与配合度 |
| **文档质量** | 10% | 输出数据的元信息是否完整 |

**评分方式**：
- 1–5星制，允许半星
- 必须填写文字评价（防止随意打分）
- 评价提交后不可修改（但可在24小时内补充）

**信誉计算**：
```
生产者信誉 = 历史评价加权平均 × 时间衰减系数 + 商场验证加分
```
- 近期评价权重更高
- 商场抽检验证通过可额外加分

### 1.4 蓝图进化建议器

**功能**：基于本次任务数据，建议优化下次任务蓝图。

**建议类型**：
| 类型 | 触发条件 | 示例 |
|------|---------|------|
| **参数优化** | 本次调节频繁 | "建议将初始功率设为-5dB，减少调节次数" |
| **流程优化** | 某步骤耗时过长 | "建议将预热步骤从生产者端移至商场预处理" |
| **风险预警** | 本次出现异常 | "建议增加功率计自检步骤，避免异常码-999" |
| **生产者推荐** | 本次生产者表现优异 | "建议将该生产者加入偏好列表" |

**呈现方式**：
- 任务完结后弹出"进化建议"面板
- 消费者可选择"采纳"（自动更新蓝图模板）或"忽略"
- 被采纳的建议计入AICoder进化积分

**边界**：
- 建议仅供参考，消费者拥有最终决定权
- 建议不得修改契约中的安全约束（如最大激励功率上限）

## 二、完结阶段的决策权归属

| 决策点 | 决策主体 | 工具角色 |
|--------|---------|---------|
| 成果验收 | 消费者 | 验收面板提供数据证据 |
| 归档确认 | 消费者 + 商场 | 打包器提供归档能力 |
| 生产者评价 | 消费者 | 评价器提供评分通道 |
| 蓝图进化 | 消费者 | 建议器提供优化建议 |

---

## 三、与三权分立的衔接

- **消费者所有权**：归档包中的蓝图归消费者所有，可自由迁移
- **AICoder设计权**：蓝图进化建议器由AICoder驱动，但消费者掌握采纳权
- **商场服务权**：归档存储由商场提供，但消费者拥有下载与删除权
