# 任务发起与批准工具设计 v1.0

> **阶段覆盖**：任务生命周期第一阶段（发起）与第二阶段（批准）
> **核心目标**：将消费者的"意向"转化为可执行、可验证、可批准的契约

---

## 一、任务发起工具族（Conception）

### 1.1 任务蓝图编辑器

**功能**：消费者以结构化方式描述任务需求。

**输入要素**：
- **输入定义**：数据来源、格式、采样率、触发条件
- **输出定义**：期望数据产物、精度要求、交付格式
- **约束条件**：时间上限、资源上限、安全等级、保密要求
- **生产者偏好**：指定/排除某些生产者、信誉等级门槛

**UI呈现**：
- 左侧：蓝图结构树（可折叠）
- 右侧：属性编辑器（带单位提示与边界校验）
- 底部：实时契约预览（人类可读摘要）

**安全铁律**：
- 蓝图数据在UI本地缓存，提交时加密传输至商场
- 消费者拥有蓝图的完整所有权，可随时导出/迁移

---

### 1.2 生产者匹配探针

**功能**：扫描可用生产者池，按能力标签筛选候选者。

**匹配维度**：
| 维度 | 说明 | 权重 |
|------|------|------|
| 能力标签 | 生产者声明的硬件/软件能力 | 高 |
| 历史成功率 | 该生产者近N次任务成功率 | 高 |
| 当前负载 | 生产者正在执行的任务数与资源占用 | 中 |
| 信誉评分 | 消费者评价加权平均值 | 中 |
| 安全等级 | 生产者通过的安全认证级别 | 高 |

**输出**：候选生产者列表，按匹配度排序，附带风险提示。

**载体**：Worker（需访问生产者注册表与信誉数据库）。

---

### 1.3 代价评估计算器

**功能**：基于历史数据估算时间、资源、风险代价。

**估算模型**：
```
总代价 = 基础执行代价 + IO传输代价 + 生产者协同代价 + 风险缓冲代价
```

**消费者可见**：
- 预估完成时间（乐观/悲观/最可能三值）
- 预估资源消耗（SHM占用、算力占用）
- 风险等级（绿/黄/红）及主要风险源

**不确定性处理**：
- 当被测件存在已知滞后（如功率测量场景），自动加入缓冲系数
- 当生产者历史数据不足，标注"估算置信度低"

---

### 1.4 契约生成器

**功能**：将消费者需求与生产者能力转化为可执行契约。

**契约结构**：
```json
{
  "contract_id": "uuid",
  "consumer_blueprint_hash": "sha256",
  "producers": [
    {"producer_id": "...", "role": "signal_source", "obligations": [...]}
  ],
  "execution_plan": {"sequence": [...], "fork_join": [...]},
  "constraints": {"max_duration": 300, "max_retries": 3},
  "approval_required": ["consumer", "mall"],
  "signature": "..."
}
```

**三权分立映射**：
- 消费者批准：确认"这是我的需求"
- 商场批准：确认"资源可调度、契约合法"
- AICoder设计：确认"契约可编译为执行序列"

---

## 二、任务批准工具族（Ratification）

### 2.1 契约可视化面板

**功能**：将技术契约转化为人类可读的交易条款。

**呈现方式**：
- **摘要卡片**：谁在做什么，多久完成，多少钱/资源
- **责任矩阵**：消费者责任 / 生产者责任 / 商场责任（三权分立可视化）
- **风险告知**：用红色高亮潜在风险点，附历史同类任务失败率

**禁止**：
- 禁止隐藏任何责任条款（消费者知情权铁律）
- 禁止使用技术术语替代人类语言（除非附带解释）

---

### 2.2 双向确认签名器

**功能**：消费者与商场共同批准契约。

**流程**：
```
消费者点击"确认" → UI生成确认包(消费者私钥签名)
    ↓
商场验证签名 → 商场附加批准签名
    ↓
契约进入"已批准"状态，锁定资源
```

**关键设计**：
- 消费者确认前，契约处于"草案"状态，可随时修改
- 一旦双方签名，契约进入"冻结"状态，修改需重新发起
- 签名数据永久存入审计日志

---

### 2.3 沙箱预演器

**功能**：在沙箱商场中模拟任务执行，验证可行性。

**预演范围**：
- 验证生产者间的数据格式兼容性
- 验证执行序列是否存在死锁或循环依赖
- 验证IO带宽是否满足实时要求
- 验证异常路径（如生产者中途离线）

**预演结果**：
- 通过：进入正式批准流程
- 警告：指出潜在问题，消费者可选择忽略或修正
- 失败：禁止批准，必须修正蓝图

**安全铁律（v1.3）**：沙箱预演器运行在全透明非密系统，不得使用任何加密措施，确保调试可见性。

## 三、发起与批准阶段的决策权归属

| 决策点 | 决策主体 | 工具角色 |
|--------|---------|---------|
| 蓝图内容 | 消费者 | 编辑器提供结构化能力 |
| 生产者选择 | 消费者 | 探针提供候选列表 |
| 代价接受 | 消费者 | 计算器提供估算数据 |
| 契约批准 | 消费者 + 商场 | 签名器提供确认通道 |
| 预演通过 | 商场（技术层面） | 预演器提供验证能力 |
