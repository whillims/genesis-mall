## 一、核心概念：用户 ≠ 消费者

### 1.1 范式定义

| 概念 | 定义 | 类比 |
|------|------|------|
| **用户 (User)** | 人类操作者，拥有独立身份和偏好，是消费者的**集合持有者**和**编排者** | 乐团指挥 |
| **消费者 (Consumer)** | 函数级实体，以消费意图驱动，在SHM生态中执行数据消费 | 乐团乐手 |
| **消费者相 (Phase)** | 消费者对外呈现的观测界面(UI) | 乐器的音色 |

**铁律**：一个用户可以拥有零个到多个消费者。用户不直接消费数据，用户通过编排消费者的组合来实现自己的目标。

### 1.2 与现有体系的关系

```
用户 (User)                          ← 新增层
  ├── 消费者A (终端型 CT)             ← 现有体系
  ├── 消费者B (分析型 CA)             ← 现有体系
  ├── 消费者C (控制型 CC)             ← 现有体系
  └── 消费者D (容器型 CCn)            ← 现有体系
        ├── 消费者E (终端型 CT)       ← 容器内嵌套
        └── 消费者F (文件型 CF)       ← 容器内嵌套
```

用户画像 = 用户身份信息 + 消费者集合 + 消费者间编排规则 + 偏好配置

## 二、用户画像数据结构

### 2.1 用户身份 (User Identity)

```c
struct UserIdentity {
    char   user_id[32];           // 用户唯一标识 UUID
    char   display_name[64];      // 显示名称
    char   avatar_hash[32];       // 头像哈希 (可选)
    uint64_t created_at_ns;       // 创建时间 (纳秒时间戳)
    uint64_t updated_at_ns;       // 最后更新时间
    uint32_t trust_level;         // 信任等级 0-100
    uint8_t  state;               // 状态: 0=活跃 1=冻结 2=归档
};
```

### 2.2 消费者集合 (Consumer Collection)

```c
struct ConsumerCollection {
    char   user_id[32];           // 所属用户ID
    uint32_t consumer_count;      // 消费者数量
    // 消费者引用列表 (每个引用 64 字节)
    struct ConsumerRef {
        char   consumer_id[32];   // 消费者ID
        char   alias[32];         // 用户给消费者起的别名
        uint8_t  pinned;          // 是否置顶
        uint32_t order;           // 排序权重
    } refs[MAX_CONSUMERS_PER_USER]; // MAX=256
};
```

### 2.3 消费者相模板 (Phase Template)

用户创建消费者时，可以选择：

| 来源 | 说明 | 示例 |
|------|------|------|
| **空白蓝图** | 用户从零描述需求，AICoder 编译生成消费者 | "我需要一个显示频谱数据的面板" |
| **商场模板** | 商场提供的预置消费者模板，用户修改参数 | "终端日志模板 + 自定义配色" |
| **克隆现有** | 基于用户已有的消费者复制并修改 | "复制我的频谱面板，改为显示网络数据" |
| **蓝图导入** | 从外部导入符合规范的蓝图文件 | 上传 BP-xxxx-consumer-xxx.md |

### 3.2 各步骤详解

#### 步骤1：创建用户身份

- 用户首次进入系统时自动创建
- 生成 user_id (UUID)
- 设置默认偏好
- 初始化空的消费者集合

#### 步骤2：选择消费者相

用户通过以下方式添加消费者：

**方式A：从商场模板库选择**
```
商场模板库
├── 终端型模板
│   ├── 实时日志面板 (CT-L0-S0)
│   ├── 系统状态监控 (CT-L0-S1)
│   └── 调试控制台 (CT-L1-S0)
├── 分析型模板
│   ├── 频谱瀑布图 (CA-L1-S1)
│   ├── 趋势折线图 (CA-L2-S1)
│   └── 统计仪表盘 (CA-L2-S0)
├── 文件型模板
│   ├── 数据归档器 (CF-L2-S1)
│   └── 报告生成器 (CF-L3-S2)
├── 控制型模板
│   ├── 设备控制面板 (CC-L0-S3)
│   └── 参数调节器 (CC-L1-S2)
└── 容器型模板
    ├── 多面板工作台 (CCn-L1-S1)
    └── 全局监控大屏 (CCn-L0-S0)
```

**方式B：提交空白蓝图**
用户用自然语言描述需求，AICoder 将其编译为消费者蓝图。

**方式C：克隆已有消费者**
基于用户自己已有的消费者复制，修改参数后生成新消费者。

#### 步骤3：定制消费者相

用户可定制的属性：

| 定制维度 | 说明 | 示例 |
|---------|------|------|
| **数据源** | 订阅哪个生产者 | "订阅频谱仪输出" |
| **时效等级** | L0~L3 | "实时显示 (L0)" |
| **布局** | 在容器中的位置和大小 | "占据左半区域" |
| **样式** | 配色、字体、动画 | "深色主题，琥珀色高亮" |
| **交互** | 点击、悬浮、快捷键 | "点击数据点显示详情" |
| **告警** | 阈值触发条件 | "超过阈值时红色闪烁" |
| **别名** | 用户自定义名称 | "我的频谱面板" |

#### 步骤4：提交蓝图

用户完成定制后，将消费者相配置提交为蓝图：

```
蓝图内容 = 用户身份 + 消费者集合 + 各消费者的定制参数 + 编排规则
```

蓝图格式遵循《蓝图标准格式总则v1.0》，存储于 `design/blueprints/consumer/`。

#### 步骤5：AICoder 编译 UI

AICoder 接收蓝图后执行：
1. **D1 形式规范审查**：蓝图格式合规性
2. **D2 安全铁律审查**：无越权访问、无OOP
3. **D3 语义一致性**：消费者间无SHM冲突
4. **D4 性能资源**：SHM配额不超限
5. **D5 测试覆盖**：生成验收测试
6. **D6 编译可行**：生成可运行的UI代码
7. **D7 生态兼容**：与现有消费者兼容

AICoder 产出：
- 消费者相 UI 预览（静态HTML/交互原型）
- 消费者函数源代码（纯函数Python）
- 验收测试用例

#### 步骤6：用户审批

用户在沙箱中预览 AICoder 生成的 UI，三种结果：

| 用户决策 | 后续动作 |
|---------|---------|
| **批准** | 进入授权流程，生成授权文件，部署到商场 |
| **修改** | 返回步骤3，附带修改意见，AICoder 重新编译 |
| **拒绝** | 蓝图标记为 REJECTED，记录拒绝原因 |

#### 步骤7：迭代修改

用户可对已批准的消费者相发起修改请求：
- 修改请求作为新蓝图提交（保留版本历史）
- 修改后的蓝图需重新经过 AICoder 编译和用户审批

#### 步骤8：归档

- 已批准的消费者相部署到商场
- 蓝图归档到用户画像中
- 授权文件进入 mall_inbox/authorized/

## 四、函数签名

### 4.1 Worker 架构说明

本蓝图涉及的 Worker 分两类：

| 类型 | 说明 | 示例 |
|------|------|------|
| **FastAPI Worker** | 独立进程，常驻运行，提供 HTTP API | `user_profile_api.py` (uvicorn) |
| **函数式 Worker** | 纯函数集合，按需调用 | `user_profile_ops.py` |

函数式 Worker 在需要 open/close 闭环时，必须将所需函数封装在 `workername_main()` 中：

```
workername_main() 标准闭环流程:
  open()    → 初始化资源（SHM连接、状态加载）
  set()     → 配置参数（消费者相配置、布局参数）
  daq()     → 数据采集（读取生产者SHM矢量）
  close()   → 释放资源（SHM断开、状态保存）
  analysis()→ 结果分析（生成UI渲染数据）
  提交结果  → 写入输出SHM或返回调用者
```

## 六、SHM 矢量分配

### 6.1 用户画像 SHM 布局

```
用户画像 SHM 区域 (每用户最大 4KB)
├── [0:32]     UserIdentity (身份)
├── [32:64]    UserPreferences (偏好)
├── [64:96]    ConsumerCollectionHeader (集合头)
├── [96:4KB]   ConsumerRef[] (消费者引用列表)
└── [4KB:]     保留区
```

### 6.2 消费者相配置 SHM

每个消费者相的配置独立存储，不占用用户画像 SHM：

```
消费者相配置 SHM (每相最大 1KB)
├── [0:32]     consumer_id
├── [32:96]    相配置 (数据源、时效、样式参数)
├── [96:128]   布局配置 (位置、尺寸、层级)
├── [128:160]  交互配置 (告警、快捷键)
└── [160:1KB]  保留区
```

## 七、安全约束

### 7.1 用户权限边界

| 操作 | 权限要求 |
|------|---------|
| 创建用户画像 | 无需授权（自动） |
| 查看自己的画像 | 用户自身 |
| 修改自己的偏好 | 用户自身 |
| 添加/移除消费者 | 用户自身 |
| 提交消费者相蓝图 | 用户自身 |
| 审批/拒绝蓝图 | 用户自身（仅自己的蓝图） |
| 查看他人画像 | 需 S0 级消费者或管理员权限 |
| 修改他人画像 | 禁止（安全铁律） |

### 7.2 隔离铁律

- **U-1**: 用户之间不得互相读取消费者集合配置
- **U-2**: 用户的消费者相之间通过标准SHM协议通信，不得直接共享内存
- **U-3**: 用户删除消费者时，该消费者的SHM矢量由商场回收，不得残留
- **U-4**: AICoder 编译用户蓝图时，不得访问其他用户的画像数据

## 八、与现有体系的集成点

### 8.1 消费者展示广场 (Consumer Plaza)

用户画像构建器产出的消费者集合，可直接渲染为 Consumer Plaza：

```
用户画像 → Consumer Collection → Consumer Plaza (Web)
                                      ├── 消费者A相 (独立渲染)
                                      ├── 消费者B相 (独立渲染)
                                      └── 消费者C相 (独立渲染)
```

### 8.2 意图提交

用户通过消费者相的操作（如点击"开始采集"），自动生成消费意图并提交给商场：

```
用户操作 → 消费者相 → IntentVector → 商场意图路由 → 生产者匹配
```

### 8.3 容器型消费者增强

用户画像本质上是容器型消费者(CCn)的**人类可操作入口**：

- 容器型消费者(CCn) = 程序化编排
- 用户画像(User Profile) = 人类可感知的编排界面

两者共享同一套SHM矢量结构，但入口不同。
